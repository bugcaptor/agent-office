# 원본 IDE 에이전트의 캐릭터 말투

상태: 구현 정본. KBM #2w7. 공식 지원 확인일: 2026-09-12.

IDE 관찰 연결의 목적은 원본 대화를 계속 사용하는 것이다. 말투 설정도 그 대화의
답변을 대상으로 하며, Agent Office 알림 문구를 바꾸는 기능과 구분한다.
관찰 연결 자체에는 입력 채널이 없다. 말투 준비는 별도 데스크톱 IPC를 사용한다.

## 공식 지원과 적용 범위

| 경로 | 지원과 시점 | 적용 범위 |
|---|---|---|
| Claude Code Output styles | 사용자 스타일 파일을 만들고 VS Code에서 선택한다. VS Code 선택 메뉴는 2.1.257 이상, 변경 후 다음 사용자 메시지부터 반영하는 동작은 2.1.251 이상이다. | 파일은 사용자에게 제공되는 선택지다. 선택은 프로젝트의 `.claude/settings.local.json`에 저장되므로 연결한 한 대화에 한정되지 않는다. 설정 위치가 main checkout이면 이를 읽는 다른 워크트리에도 영향을 줄 수 있다. |
| Codex `AGENTS.md` | 시작 시 읽는 공식 프로젝트 지침이다. 기존 특정 IDE 대화에 외부에서 즉시 적용하는 경로는 확인하지 못했다. | 같은 경로에서 지침을 읽는 다른 세션에도 영향을 주므로 캐릭터별 설정에 사용하지 않는다. |
| Codex `/personality` | 지원 모델에서 `none`, `friendly`, `pragmatic`을 선택한다. | 임의의 캐릭터 프롬프트를 등록하는 기능이 아니므로 캐릭터 말투의 대체 수단으로 쓰지 않는다. |
| Codex 사용자 메시지 | 말투 지침을 복사해 사용자가 원하는 IDE 대화에 직접 보내는 흐름을 제공한다. | 전송한 대화의 일반 사용자 요청이다. 시스템 지침 주입이나 영구 설정이 아니며 응답 준수·후속 지속을 자동 보장하지 않는다. |

Claude의 스타일은 기본 시스템 프롬프트를 조정한다. `keep-coding-instructions: true`를
반드시 넣어 코딩 지침을 보존하고, 생성 본문도 캐릭터 프롬프트를 말투에만 사용하도록
안내한다. IDE에서 제공하는 공식 선택 UI를 사용하고 외부에서 `outputStyle` 설정을
자동 편집하지 않는다. 문서에 설정 직접 편집 경로가 있어도 특정 관찰 대화만 대상으로
삼는 API라는 뜻은 아니다.
스타일 대상은 main conversation과 fork이며 일반 서브에이전트 응답은 포함하지 않는다.

로컬 설치 증거: Claude CLI와 VS Code 확장은 각각 2.1.269, Codex CLI는 0.154.0이었다.
CLI 버전을 IDE의 지원 여부로 대신 판단하지 않는다. 공식 Claude 확장 2.1.269의
`extension.js`와 번들 CLI를 정적으로 검사하여 `CLAUDE_CONFIG_DIR` 또는 `~/.claude` 아래
`output-styles`를 사용함을 확인했다. 이는 공식 settings 문서의 설정 홈 변경 설명을
보완하는 설치본 증거다. 확장은 CLI가 반환한 `user_output_styles_dir`을 우선하며
user/managed settings의 환경 설정을 반영할 수 있으므로 앱의 환경만으로 IDE 경로를
확정하지 않는다. 사용자 설정과 대화 기록은 이 검사에서 읽거나 수정하지 않았다.

## 사용자 흐름

1. IDE 세션을 캐릭터에 연결하고 외부 연결 패널의 말투 설정을 연다. 연결 당시
   공급자·작업 폴더·원본 대화 ID를 확인한다. 캐릭터 프로필에 말투가 비어 있으면
   먼저 프로필을 편집한다.
2. Claude는 생성할 스타일 내용과 경로, 선택 후 같은 프로젝트의 다른 세션에
   미칠 영향을 확인한 뒤 스타일 파일을 준비한다. 이때 기존 선택값을 기억해 둔다.
   기본 경로는 `~/.claude/output-styles/`이며 앱에 `CLAUDE_CONFIG_DIR`이 설정되어
   있으면 그 디렉터리를 사용한다. IDE와 앱이 같은 Claude 설정 디렉터리를 쓰는지
   확인한다. 다르면 원본을 유지하고 IDE의 `output-styles` 폴더로 생성 파일을 복사한다.
   직접 복사한 파일의 위치와 정리도 사용자가 관리한다.
   파일 생성만으로 IDE에서 스타일이 선택되지는 않는다.
3. VS Code의 Claude 입력창에서 `/` → **Customize** → **Output styles**를 열고 표시된 스타일 이름을
   선택한다. 목록에 없으면 확장 버전과 설정 디렉터리를 확인하고 창을 다시 불러온다.
   이전 버전은 확장을 업데이트한다. 구버전 CLI의 `/clear`나 새 세션은 대화 문맥 또는
   관찰 연결 대상을 바꾸므로 자동 실행하지 않는다.
4. Codex는 표시된 말투 지침을 복사한 뒤 원하는 원본 대화에 직접 붙여넣고 보낸다.
   이 메시지는 기존 코딩·프로젝트·안전 지침을 유지하면서 답변 말투만 요청한다.
5. 원본 IDE에서 짧은 질문을 보내 답변을 직접 확인하고 Agent Office에서 확인 사실을
   기록한다. 파일 생성·복사·활동 이벤트 수신은 실제 말투 적용의 증거로 취급하지 않는다.
   확인 표시는 사용자 신고이며 앱이 대화 내용을 검사한 결과가 아니다.

## 보존·변경·해제

- `AGENTS.md`, `CLAUDE.md`, Claude 선택 설정, Codex 설정 및 관찰 기록을 수정하지 않는다.
- 생성 파일 이름은 캐릭터와 프롬프트 내용에 묶인다. 기존 파일이 같은 내용이면 재사용하며
  다른 내용이면 덮어쓰지 않고 오류로 알린다. 프롬프트 변경은 새 파일을 준비하고
  IDE에서 다시 선택해야 한다. 이전 파일과 기존 IDE 선택은 그대로 남는다.
- 연결 해제·캐릭터 교체·앱 종료는 IDE 말투를 되돌리지 않는다. Claude는 같은 프로젝트의
  Output styles에서 이전 스타일을 다시 선택한다. 이전값을 모르면 Default를 선택할 수
  있지만 이것을 원래 설정의 정확한 복원이라고 표시하지 않는다.
- 생성 스타일을 지우려면 먼저 해당 스타일을 사용하는 프로젝트에서 다른 스타일을 선택한
  뒤 표시된 파일만 직접 삭제한다. 다른 프로젝트가 그 사용자 스타일을 선택했을 수도
  있으므로 앱은 연결 해제 시 자동 삭제하지 않는다.
- Codex에 보낸 메시지는 대화 기록에 남는다. 원래 말투로 돌아가도록 새 메시지로 요청하거나
  새 대화를 시작한다. 메시지 삭제·설정 복원·과거 답변 변경은 앱이 수행하지 않는다.
- 사용자 응답 확인은 현재 연결과 현재 프로필에 대한 화면 내 기록이다. 프롬프트 변경,
  재연결, 패널 재마운트 또는 앱 재시작 후 자동으로 적용 완료 상태를 복원하지 않는다.
  다른 세션이 Claude 선택 설정을 바꾸더라도 과거 사용자 확인을 실시간 검증으로 해석하지 않는다.

## 구현 경계

`get_ide_persona`는 검증된 VS Code 관찰 연결과 저장된 캐릭터 프로필로 준비 내용을
조회한다. 일반 셸 attach, PTY, 출처를 검증하지 않은 CLI 관찰 연결에는 제공하지 않는다.
작업 폴더는 연결 당시 값을 사용하며 현재 프로필의 폴더와 달라졌다면 재연결이 필요하다.
`prepare_ide_persona`는 동일 연결 ID와 IPC 시작 시 저장된 프로필의 프롬프트를 검사한 후
Claude 스타일만 생성한다. 파일 쓰기 직전 연결을 다시 확인하되 프로필 저장소를 잠그지는
않는다. 생성 도중 프로필이 바뀌면 선택되지 않은 이전 내용의 파일이 남을 수 있으나
프런트는 그 결과로 준비·응답 확인 상태를 갱신하지 않는다.
Codex에는 스타일 생성 명령을 사용하지 않는다. 두 명령은 웹 원격 제어에 노출하지 않는다.

프런트는 프로필 저장 지연을 flush한 뒤 조회·생성하며, 오래된 비동기 결과를 버린다.
응답 본문이나 설정 선택을 감지해 상태를 올리는 로직은 없다. `vscode-ext`와 `/v1/send`는
변경하지 않는다.

## 검증과 실기 인수

자동 검사는 생성 파일의 형식, 동일 파일 재사용, 사용자 파일 보존, 경로와 연결 검증,
준비/복사 실패 및 실제 응답 확인의 상태 구분을 다룬다. 타입 검사와 프런트·네이티브
전체 테스트를 수행한다.

2026-09-12 검증 결과: `npx tsc --noEmit` 성공, 프런트 202파일/2,907개 테스트 통과,
네이티브 총 1,629개 통과/30개 ignored. 네이티브 전체 검사는 샌드박스의 로컬 포트
제한을 해제한 환경에서 통과했다. 6개 언어 키·플레이스홀더 일치 검사도 포함한다.
Safari 가상 연결 화면에서 Claude 파일 준비 후에도 IDE 선택 필요 상태를 유지하고,
명시적인 사용자 확인 후에만 확인 문구가 바뀌는 흐름과 Codex 안내를 확인했다.
이 화면 검증은 가상 IPC를 사용했으며 실제 사용자 설정 파일이나 원본 IDE 대화는
변경하지 않았다. 설치된 Agent Office를 교체하지 않았고 `vscode-ext` 변경도 없다.

실제 IDE 인수는 다음 항목을 별도로 확인한다. 테스트 통과만으로 이를 완료 처리하지 않는다.

- Claude VS Code 메뉴에 생성 스타일이 나타나고 선택 후 다음 질문에 말투가 반영되는가.
- 같은 프로젝트 설정을 읽는 두 Claude 대화·워크트리에서 선택값 공유와 반영 시점이 어떻게 보이는가.
- 원래 스타일 재선택, 캐릭터 프롬프트 변경, 연결 해제 후 동작이 안내와 일치하는가.
- Codex의 원하는 대화에 복사한 지침을 보내 실제 답변 말투와 되돌리기 요청을 확인했는가.
- 구버전 확장, 서로 다른 `CLAUDE_CONFIG_DIR`, 읽기 전용 스타일 폴더에서 안내가 유효한가.
