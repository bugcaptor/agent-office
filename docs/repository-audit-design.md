# 저장소 일괄 점검

- 상태: 정본 — 구현 완료 (2026-09-06)
- 진입점: 모든 풍경의 오피스 배경에 놓인 서버 컴퓨터/랙

## 1. 목적

Agent Office에서 작업한 적이 있거나 현재 프로필에 연결된 Git 저장소를 한 화면에서 점검한다. 사용자가 먼저 볼 것은 저장소 이름순 목록이 아니라 **지금 조치가 필요한 저장소**다. 각 행에서 해당 저장소의 외부 OS 터미널을 바로 열 수 있어야 한다.

이 기능은 원격 서버의 최신 상태를 확인하는 동기화 도구가 아니다. 로컬 작업 트리와 로컬에 저장된 remote-tracking ref를 읽는 빠르고 비파괴적인 현황판이다.

## 2. 진입과 화면

- 밝음·미드나이트·벚꽃 등 모든 오피스 풍경에 클릭 가능한 서버 컴퓨터 또는 서버 랙을 둔다.
- 장식물은 풍경에 어울리게 표현하되, 어느 풍경에서도 같은 저장소 점검 화면을 연다.
- 저장소 점검 화면은 모달 또는 그에 준하는 오버레이이며 기존 터미널 세션을 종료하거나 가리지 않은 상태로 닫을 수 있다.
- 화면을 열 때 점검을 실행하고, 사용자가 같은 화면에서 다시 점검할 수 있게 한다.
- 각 저장소 행에는 경로, 요약 상태, 필요한 조치와 **OS 터미널로 열기** 동작을 제공한다. 터미널은 저장소 최상위 디렉터리에서 열린다.

서버 오브젝트의 실제 좌표·스프라이트 구성과 화면 컴포넌트 분할은 각 풍경 및 렌더러 구조에 맞춘다. 정본 계약은 “모든 풍경에서 발견하고 클릭할 수 있다”는 점이다.

## 3. 저장소 후보 수집

후보 cwd는 다음 두 원천의 합집합이다.

1. 영속 작업 기록인 `<app-data>/session-events/v1/*.jsonl`에 기록된 cwd
2. 현재 저장된 모든 프로필의 cwd

각 후보에 대해 Git 저장소 최상위 디렉터리를 찾는다. 저장소 내부의 서로 다른 하위 디렉터리에서 작업했더라도 최상위 디렉터리가 같으면 한 행으로 합친다. 경로 표현 차이로 중복되지 않도록 가능한 범위에서 절대 경로로 정규화한다.

- cwd가 없거나 빈 값이면 후보에서 제외한다.
- 경로가 사라졌거나 디렉터리가 아니면 목록에서 제외한다. 실제 디렉터리는 존재하지만 접근할 수 없거나 Git 저장소 상태를 읽지 못한 후보는 **조회 불가/설정 이상** 항목으로 표시할 수 있다.
- 한 후보의 오류 때문에 전체 점검을 중단하지 않는다.
- 최근 작업 시각은 그 저장소 아래 cwd를 가진 세션 이벤트 중 가장 최근 시각을 기준으로 한다. 이벤트 기록이 없는 현재 프로필 cwd는 최근 작업 시각이 없는 후보로 취급한다.

세션 이벤트 전체 기간을 후보 원천으로 사용한다. 보존 정책에 따라 이미 삭제된 과거 이벤트는 복구하거나 별도 색인하지 않는다.

## 4. 점검 범위와 안전성

점검은 읽기 전용 Git 명령과 파일 시스템 조회만 수행한다. 다음을 판정할 수 있어야 한다.

- 작업 트리/인덱스의 변경 및 새 파일: 커밋할 것이 있음
- 병합 충돌 또는 해결되지 않은 경로: 충돌 해결 필요
- upstream 대비 ahead: push할 것이 있음
- upstream 대비 behind: pull할 것이 있음
- upstream 대비 ahead이면서 behind: 분기됨(diverged), 통합 필요
- upstream 미설정, 저장소 접근 실패, Git 조회 실패 등: 설정 이상 또는 조회 불가
- 위 조치가 없는 저장소: clean

원격 상태 비교는 **현재 로컬에 저장된 remote-tracking ref**를 기준으로 한다. 화면을 열거나 새로고침할 때 `git fetch`, `git pull`, `git push` 등 네트워크 또는 저장소를 변경하는 명령을 자동 실행하지 않는다. 따라서 “pull 필요 없음”은 원격 서버의 실시간 상태가 아니라 마지막 fetch 시점 기준이다. 이 제한을 화면에서 짧게 안내한다.

충돌과 로컬 변경은 upstream 유무와 독립적으로 판정한다. 예를 들어 커밋할 변경과 push할 커밋이 동시에 있으면 두 조치를 모두 보여 줄 수 있다. 여러 상태가 함께 있을 때 한 가지 상태로 정보를 잃지 않는다.

## 5. 우선순위와 정렬

목록의 1차 정렬은 다음 세 그룹이다.

1. **조치 필요** — 충돌, diverged, 커밋할 변경, push 필요, pull 필요
2. **확인 필요** — 조회 불가, Git 설정 이상, upstream 미설정처럼 정상 여부를 확정하기 어려운 항목
3. **정상** — clean

같은 그룹에서는 최근 작업 시각이 최신인 저장소를 먼저 둔다. 시각이 같거나 없으면 표시 경로 등 안정적인 값으로 정렬해 재점검 때 행이 불필요하게 흔들리지 않게 한다.

조치 필요 그룹 안에서 충돌 또는 diverged를 더 눈에 띄게 표현할 수 있지만, 이 세부 표현이 최근 작업순이라는 보조 정렬 계약을 깨뜨려서는 안 된다. 한 저장소에 여러 조치가 있으면 모든 배지를 함께 노출한다.

## 6. 외부 터미널

행의 **OS 터미널로 열기**는 기존 외부 터미널 설정과 실행 경로를 재사용한다.

- 시작 디렉터리는 수집에 사용한 하위 cwd가 아니라 정규화된 저장소 최상위 디렉터리다.
- 터미널 열기 실패는 해당 행에서 알리고 점검 결과는 유지한다.
- 저장소 점검 자체는 터미널 세션을 새로 만들거나 기존 캐릭터 세션에 명령을 주입하지 않는다.

## 7. 상태 계약

렌더러가 받는 결과는 구현 언어와 파일 배치에 관계없이 저장소별로 다음 의미를 제공해야 한다.

- 정규화된 저장소 경로와 표시 이름
- 최근 작업 시각(없을 수 있음)
- 변경/충돌 여부
- upstream 존재 여부 및 ahead/behind 수
- 조회 오류 또는 설정 경고(없을 수 있음)
- 파생된 정렬 그룹

표시용 문구는 `src/shared/i18n/locales/`의 번역 카탈로그를 사용한다. Git의 원문 오류를 그대로 주 UI 문자열로 삼지 않고, 사용자용 요약과 진단 세부정보를 구분한다.

## 8. 검증 기준

- 모든 지원 풍경에서 서버 컴퓨터/랙을 클릭해 같은 점검 화면을 열 수 있다.
- 세션 이벤트 cwd와 현재 프로필 cwd가 모두 후보가 되며, 같은 저장소의 하위 cwd는 한 행으로 합쳐진다.
- 이미 사라졌거나 디렉터리가 아닌 후보 경로는 목록에 표시하지 않는다.
- conflict/diverged/commit/push/pull이 있는 저장소가 clean 저장소보다 위에 온다.
- 조회 불가/설정 이상은 조치 필요와 clean 사이에 온다.
- 같은 그룹에서는 최근 작업한 저장소가 먼저 온다.
- 자동 네트워크 접근과 자동 fetch가 발생하지 않는다.
- 행의 외부 터미널 동작이 저장소 최상위 디렉터리에서 터미널을 연다.
- 일부 경로 또는 Git 조회가 실패해도 나머지 저장소 결과를 볼 수 있다.
