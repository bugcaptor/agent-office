# 에이전트 호감도 설계

상태: 기획 확정·구현 전 — 2026-09-05, kbm #2rv.

사용자가 터미널 작업을 마치며 칭찬·격려·질책을 선택하고, 그 기록이 캐릭터와의 관계로 쌓인다. 이 문서는 합의된 제품 방향과 구현할 동작을 서술한다. 현재 앱에 구현된 기능은 아니다.

## 1. 합의된 범위

- 기본 OFF인 전역 opt-in 기능. 사용자가 직접 켜야 활성화된다.
- **터미널 종료 또는 재시작 때, 해당 세션에 유의미한 LLM 사용 기록이 있을 때만 평가 팝업을 표시한다.** 매 답변 완료에는 표시하지 않는다.
- 판정·계산·반응 대사는 모두 로컬 규칙으로 처리한다. LLM 호출, 자유 텍스트 성격 해석, 터미널/시스템 프롬프트 주입을 하지 않는다.
- 에이전트별 호감도, 관계 단계, 반응 유형별 고정 대사, 작은 픽셀 연출, 평가 이력과 수정이 v1 범위다.
- 실제 코딩 능력, 지시 수행, 우수사원 선정에는 영향을 주지 않는다.

## 2. 활성화

`AppSettings.affinityEnabled`를 기본 false로 추가한다. 앱 설정에서 직접 켜며 CLI가 대신 활성화하지 못하게 한다. 기존 요약·일기·TTS 설정과 독립이다.

켜면 각 캐릭터는 호감도 20에서 시작한다. 끄면 관계와 이력은 보존하고 신규 평가·반응·관련 UI를 중지한다. 다시 켜도 꺼져 있던 동안의 세션에 평가를 소급 요청하지 않는다. 이미 열린 세션 중간에 켜면 활성화 이후의 활동만 자격 판정에 포함한다.

호감도는 영속 캐릭터 키 `agentId`에 귀속한다. 개명·외형 변경·터미널 재시작으로 초기화하지 않는다. 복제로 생긴 새 캐릭터 ID에는 기존 관계를 복사하지 않는다.

## 3. 유의미한 LLM 사용

다음은 제품 요구를 구체화한 v1 판정 규칙이다. 최소 시간·비용·토큰 개수 문턱은 두지 않는다. 짧은 답변도 실제 사용이고, 도중에 중단한 작업도 사용 근거가 있으면 평가할 수 있다.

**우선 근거:** 종료 대상 `sessionId`와 일치하는 세션 사용량에서 활성화 이후 `input + output + cacheRead + cacheWrite > 0`이 확인된다. 중간 토큰 기록(`partial=true`)도 포함한다. 계정 전체 누적 사용량이나 잔여 한도는 쓰지 않는다.

**토큰 기록을 제공하지 못하는 공급자의 보조 근거:** 같은 세션·관찰 구간에서 `prompt` 이후 LLM의 `tool` 또는 응답 완료 `stop`이 확인된다. 초기 idle이나 프롬프트 제출만으로 인정하지 않는다. 구현 시 공급자별 stop의 의미와 요청 연결을 검증하며, 시작 상태나 종료 정리 신호를 응답 완료로 오인하지 않아야 한다.

인정하지 않는 근거는 셸 출력·열어 둔 시간·CLI 실행/접속·시작 명령·사용자가 직접 실행한 셸 명령·캐릭터의 과거 세션 통계다. 종료 코드로 결과를 평가하거나 자동 가감점하지 않는다. 봇의 실제 LLM 작업도 사용 근거에 포함하되 평가는 사용자가 직접 한다.

관찰 비활성화/공급자 미지원으로 근거를 확인하지 못하면 팝업을 생략한다. 호감도 기능이 다른 수집 기능을 자동으로 켜지 않는다. 설정 도움말에는 평가에 세션 활동 기록이 필요함을 설명한다.

### 기존 구조에서 확인한 근거

- `src/shared/types/notification.ts`: `TurnUsageEvent`에 `agentId`, `sessionId`, `tokens`, `partial`이 있다. 백엔드는 토큰이 전부 0인 기록을 제외한다.
- `src/renderer/store/appStore.ts`: `sessionUsage[agentId]`는 세션 ID와 누적 사용량을 갖고 새 ID가 오면 초기화된다.
- 이벤트 로그 `session-events/v1/YYYY-MM-DD.jsonl`에도 세션별 usage/stop 기록이 남는다. 즉시 팝업은 현재 세션 스냅샷을 우선 사용한다.
- resume/입양된 native 세션의 과거 누적 사용량을 새 활동으로 오인하지 않도록 이번 터미널 구간과 활성화 시점의 기준점을 보존해야 한다.

## 4. 종료·재시작과 팝업

| 상황 | 동작 |
|---|---|
| 일반 터미널 실제 종료 + 유효 활동 | 종료된 세션 평가 팝업 |
| 사용자 터미널 재시작 + 유효 활동 | 이전 세션 평가 팝업. 새 터미널 시작은 평가 입력을 기다리지 않음 |
| 활동 없는 터미널 종료/재시작 | 팝업 없음 |
| 답변 완료·입력 대기 | 활동 근거만 갱신 |
| 터미널 패널/탭 숨김 | 팝업 없음 |
| tmux detach·외부 세션 연결 해제 | 작업 자체의 종료가 아니므로 팝업 없음 |
| 앱 종료·핸드오프·크래시 복구 | 팝업 없음. 다음 부팅에 과거 종료 팝업을 몰아서 띄우지 않음 |
| 퇴근 | 실제 터미널을 종료하는 경로이면 동일 자격 검사. 캐릭터 숨김 자체는 트리거가 아님 |
| 캐릭터 삭제 | 팝업 없음 |

재시작은 **dispose 호출 전에 이전 세션 ID·사용량을 확보**한다. 현재 `restartAgentSession`은 dispose 요청 후 새 세션을 만들며, 새 세션이 먼저 생기면 옛 종료 이벤트가 억제될 수 있고 사용량도 초기화된다. 종료 이벤트에만 의존해서는 재시작 평가가 누락된다.

종료/재시작 요청과 실제 종료 이벤트가 모두 들어와도 세션당 후보는 한 번만 만든다. 종료 요청 실패는 평가 후보를 만들지 않는다. dispose 응답은 종료 완료가 아닌 요청 수락이므로, 구현에서는 재시작 요청 경로의 평가 확정 지점과 실패 처리를 명시한다. 평가 도중 새 세션이 생겨도 대상은 이전 세션으로 고정한다. 이미 끝난 터미널을 재시작할 때 같은 종료를 재평가하지 않는다.

팝업은 이름·종료 시점·선택 버튼을 보여주는 작은 비차단 팝업이다. 새 터미널의 입력 포커스를 빼앗지 않는다. 여러 종료가 겹치면 큐로 한 번에 하나씩 표시한다. Esc/닫기는 건너뛰기로 처리하고 재촉하지 않는다.

```text
루비와의 작업이 끝났어요.
이전 세션 · 19:42 종료

[칭찬하기] [격려하기] [질책하기]   [건너뛰기]
```

## 5. 호감도와 평가 수정

| 선택 | 의미 | 변화 |
|---|---|---:|
| 칭찬 | 이번 결과가 마음에 든다 | +3 |
| 격려 | 고생했다. 다음에도 함께하자 | +2 |
| 질책 | 이번에는 실망했다 | -2 |
| 건너뛰기 | 평가하지 않음 | 0 |

범위는 0~100, 초기값은 20이다. 방치·미접속·건너뛰기로 감점하지 않는다. 별도 일일 횟수 제한은 두지 않는다. 한 세션에는 평가 하나만 유효하다.

프로필의 이력에서 평가를 수정하거나 건너뛰기로 바꿀 수 있다. 기존 레코드를 교체하며 추가 보상을 지급하지 않는다. 점수는 종료 시각과 고정 보조 키로 정렬한 기록을 초기값 20부터 순서대로 적용하고, 각 단계에서 0~100으로 제한한다. 과거 평가 수정 후에는 같은 순서로 재계산한다. 상한에서 잘린 값을 단순히 빼는 방식은 사용하지 않는다.

| 점수 | 관계 단계 |
|---:|---|
| 0~19 | 서먹한 사이 |
| 20~39 | 알아가는 사이 |
| 40~69 | 친숙한 사이 |
| 70~89 | 믿는 사이 |
| 90~100 | 각별한 사이 |

프로필에는 단계·진행 막대·이력을 표시한다. 단계에 따라 피드백 대사와 출근 인사를 바꾸고 상승 시 짧은 특별 반응을 보여준다. 수정으로 과거 단계 상승 연출을 일괄 재생하지 않는다.

## 6. 캐릭터 반응

장기 호감도와 직후 반응을 구분한다. 별도 기분 수치를 영속화하지 않고 기쁨/안도/반성 연출만 짧게 표시한다. 퇴근으로 캐릭터가 사라졌다면 팝업 초상과 대사로 반응한다.

자유 텍스트 `personalityPrompt`를 자동 분석하지 않는다. 프로필에서 반응 유형을 선택한다. v1 후보는 기본·자신만만·차분·수줍음·활발함이고, 미지정/알 수 없는 값은 기본으로 처리한다. 반응 유형은 프롬프트 성격이나 종족과 독립이다.

대사는 `반응 유형 × 관계 단계 × 피드백 종류`의 미리 작성된 카탈로그에서 고른다. 변형 선택에는 고정 시드를 써 리렌더마다 바뀌지 않게 한다. 모든 UI 문자열과 대사는 `src/shared/i18n/locales/`에 둔다. 기존 TTS의 LLM 리라이트를 호출하지 않으며 v1에 음성 생성은 포함하지 않는다.

자신만만한 드래곤 영애의 대사 예시:

- 칭찬: “후후, 이제야 내 진가를 알아보는군요!”
- 격려: “그대가 그렇게 말하니… 한 번 더 힘내 보겠어요.”
- 질책: “으음… 이번 지적은 받아들이겠어요.”
- 각별한 사이에서 칭찬: “당연한 결과지만… 그대에게 인정받으니 더 기쁘군요.”

## 7. 저장·통합 방향

호감도는 별도 버전 문서 `<app_data>/affinity/affinity.json`에 원자적으로 저장하는 방향을 권한다. 저장 API가 세션 키 중복과 수정 충돌을 처리하고 화면이 파일 전체를 덮어쓰지 않게 한다.

최소 저장 정보는 `version`, 에이전트 ID, 고유 터미널 구간 키, 종료 시각/원인, 활동 근거 요약, 평가 선택/수정 시각, 규칙 버전이다. 프롬프트·응답 본문을 복사할 필요는 없다. 점수는 이력에서 재구성할 수 있어야 한다. v1에서 이력을 자동 삭제하지 않는다.

현재 `AgentProfile.id`는 영속되고 세션 ID는 런타임 정보다(`src/shared/types/profile.ts`). 평가 기록에 과거 세션 ID를 저장하더라도 살아 있는 세션 ID로 취급하면 안 된다. 핸드오프/입양의 구간 연결과 기준점은 구현에서 명시적으로 다룬다.

`src/renderer/ipc/sessionBridge.ts` 및 `src-tauri/src/session/manager.rs`, `session/external.rs`의 종료 이벤트는 `intentional`만으로 재시작·퇴근·삭제·연결 해제를 구분할 수 없다. 종료 원인을 표현하는 정보를 더하고 활동 근거와 결합해야 한다. 구체적인 IPC·타입은 구현 시 확정한다.

## 8. 구현 순서와 인수 조건

1. 종료 원인·활동 근거·중복 방지 규약과 자격 판정.
2. 기본 OFF 설정, 별도 저장, 평가 교체와 점수 재계산.
3. 종료/재시작 팝업과 프로필 이력.
4. 반응 유형·번역 대사·픽셀 반응·관계 단계별 출근 인사.

인수 검증:

- 기본 OFF/중간 활성화/다시 활성화에서 평가 범위가 정확하다.
- 빈 셸, CLI 실행만, 제출만, 초기 idle, 계정 누적 사용량에는 팝업이 없다.
- 현재 구간 토큰 증가와 보조 근거를 각각 판정하고 중단 세션도 처리한다.
- 종료·재시작은 이전 세션에 한 번만 평가되며 새 터미널 입력을 방해하지 않는다.
- tmux detach, 패널 숨김, 앱 종료/핸드오프, 삭제는 평가를 만들지 않는다.
- 중복 이벤트/클릭, 점수 상하한, 과거 평가 수정, 저장 실패·재시도를 검증한다.
- LLM·요약·TTS 리라이트·PTY 입력을 호출하지 않는다.
- 실제 구현 시 `npx tsc --noEmit`, 관련 프런트/네이티브 테스트와 팝업 눈검증을 수행한다.
