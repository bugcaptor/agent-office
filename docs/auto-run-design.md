# 자동 진행 설계

상태: 정본 (2026-10-15) — 구현 완료. 설치 Tauri 앱에서 실제 CLI로 플랜 전체를 돌리는 실기 확인은 남아 있다.

업무 패널에서 루트 태스크 하나를 고르면, 그 태스크가 기다리는 선행 작업들을 한 캐릭터가 차례로 진행한다. 태스크마다 CLI 세션을 새로 시작하고, 턴이 끝날 때마다 별도의 판단자(`claude -p` 세션)에게 다음 할 일을 묻는다. 사람이 하나씩 보내고 결과를 확인하던 일을 앱이 대신 돌리되, 판단만 LLM에 맡긴다.

관련 문서: [work-panels-design.md](work-panels-design.md)(업무·보내기·모니터링·상태 전이), [session-log-design.md](session-log-design.md)(에이전트 전사).

## 왜 이 구조인가

- **캐릭터끼리 조종하지 않는다.** 한 에이전트가 다른 캐릭터 터미널을 움직이는 구조는 권한 범위, 캐릭터 간 동기화, 전역 상태 공유가 모두 새로 필요해 깨지기 쉽다. 루프는 앱이 쥐고, LLM은 결정 하나만 돌려준다.
- **태스크마다 새 세션.** 앞 태스크의 긴 맥락이 다음 태스크를 흐리지 않는다. 대신 필요한 맥락은 판단자가 남긴 인계 메모로 넘긴다.
- **판단자는 이어지는 세션.** 매번 새 `claude -p`를 부르면 지난 판단의 맥락이 사라지고 프롬프트 캐시도 깨진다. 실행마다 세션 id를 하나 정해 첫 호출은 `--session-id`, 이후는 `--resume`으로 이어 붙인다. 대화가 뒤에 덧붙기만 하므로 이전 부분은 캐시로 읽힌다(2026-10-15 실측: 두 번째 호출에서 앞 3,962토큰 전부 캐시 적중).
- **새 저장 개념을 만들지 않는다.** 묶음은 기존 선행 작업(`dependsOn`)으로, 진행 상태는 루트 업무의 필드 하나로, 대기는 기존 상태 전이(진행 중 → 검토 대기)로 해결한다.

## 용어

- **루트 태스크**: 선행 작업이 있고 담당 캐릭터가 있는 업무. 자동 진행을 여기서 시작한다. 본문은 플랜 메모로 쓰인다.
- **플랜**: 루트가 직접·간접으로 기다리는 업무 전부(선행 작업의 전이 폐포).
- **진행자**: 루트의 담당 캐릭터. 플랜의 모든 태스크를 이 캐릭터 터미널에서 실행한다.
- **판단자**: 실행마다 하나인 `claude -p` 세션. 도구 없이 텍스트만 보고 결정한다.

## 흐름

```text
[시작] ─▶ 다음 태스크 고르기 ─▶ 새 세션으로 보내기 ─▶ 턴 종료(검토 대기) 대기
              ▲                                          │
              │                       마지막 응답 읽기 ◀──┘
              │                              │
              │                  판단자(claude -p --resume)
              │       ┌──────────────┼──────────────┐
              │     next          followup         stop
              │   (완료 처리)   (같은 세션에 지시)   (일시정지)
              └───────┘              │
                                     └─▶ 턴 종료 대기
```

1. **고르기**: 플랜에서 완료가 아니고 선행 작업이 모두 완료된 업무를 찾는다. 할 일 상태인 것 중 패널 순서가 가장 앞선 것을 보낸다. 준비된 업무 가운데 진행 중·검토 대기인 것이 있으면(사람이 따로 보낸 업무) 손대지 않고 일시정지한다. 남은 업무가 없으면 끝낸다.
2. **보내기**: 기존 보내기 경로를 그대로 쓴다. 다른 점은 둘이다.
   - CLI가 돌고 있어 재시작이 필요하면 확인창 없이 재시작한다. 미제출 사람 입력이 있으면 재시작하지 않고 일시정지한다.
   - 프롬프트 본문 뒤에 자동 진행 맥락(플랜 제목, 루트 본문, 앞 태스크 인계 메모, "끝나면 바꾼 것과 검증 방법을 요약하라")을 붙인다.
   - 미배정 태스크는 보낼 때 진행자에게 배정한다.
3. **대기**: 기존 모니터링이 Stop·최종 usage에서 그 업무를 검토 대기로 바꾸면 다음 단계로 간다. 권한 승인 다이얼로그 등으로 멈춰 있으면 지금처럼 카드가 강조되고, 사람이 처리해 턴이 끝날 때까지 그냥 기다린다.
4. **판단**: 진행자 세션의 에이전트 전사에서 마지막 사용자 프롬프트 뒤의 assistant 텍스트를 읽어 판단자에게 보낸다. 판단자는 JSON 스키마로 강제된 `{decision, message, note}`를 돌려준다.
5. **적용**
   - `next`: 태스크를 완료로 바꾸고, `note`를 인계 메모로 기록한 뒤 1로 간다.
   - `followup`: `message`를 같은 세션에 프롬프트로 넣는다. 태스크당 3번까지다. 넘으면 일시정지한다.
   - `stop`: `message`를 사유로 일시정지한다.
6. **끝**: 플랜이 모두 완료되면 루트를 검토 대기로 옮기고 실행을 끝낸다. 루트 자체는 보내지 않는다.

## 판단자

- 명령: `claude -p --safe-mode --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --output-format json --json-schema <스키마> (--session-id <id> | --resume <id>) [--model <모델>]`. 프롬프트는 stdin으로 넣는다.
- 작업 폴더는 `<app_data>/auto-run/judge`로 고정한다. Claude는 세션을 cwd별로 저장하므로 `--resume`이 같은 폴더에서 돌아야 찾고, 사용자 프로젝트의 세션 목록에도 섞이지 않는다.
- `--safe-mode`로 CLAUDE.md·훅·플러그인·MCP를 끈다. 도구가 없으니 판단자는 아무것도 실행하지 못한다. 검증은 작업자 세션이 하고 요약으로 보고한다.
- 모델: 루트 업무의 에이전트 설정이 Claude면 그 모델, 아니면 Claude 기본값.
- 첫 호출에는 역할·결정 규칙·플랜 제목·루트 본문·태스크 목록을 넣는다. 이후 호출에는 그 턴의 사건(태스크 제목, 후속 지시 횟수, 작업자 응답)만 넣는다. 루트 본문이 바뀌었을 때만 새 본문을 다시 넣는다. 사람이 진행 중에 루트 본문을 고쳐 방향을 바꿀 수 있는 통로다.
- 판단자 세션이 없어졌거나 호출이 실패하면 일시정지한다. 사람이 계속을 누르면 같은 세션으로 다시 시도한다. 계속 실패하면 끝내고 새로 시작한다(새 판단자 세션).
- 호출마다 `total_cost_usd`를 더해 실행 비용으로 보여준다.

## 마지막 응답 읽기

`work_last_reply(agentId, cli, cwd)`가 세션 로그와 같은 전사 소스(Claude: 훅이 기록한 transcript_path, Codex: cwd의 최신 rollout)에서 파일 끝 1MiB를 읽어, 마지막 사용자 텍스트 뒤의 assistant 텍스트를 합쳐 돌려준다(32,000자 상한, 앞쪽을 자른다). 서브에이전트 대화는 뺀다. 못 찾으면 비어 있다는 사실을 판단자에게 그대로 알린다.

Stop 알림의 메시지는 300자로 잘려 있어 판단에 쓰지 않는다. agy·kilo·pi 작업자는 응답을 읽지 않는다(판단자는 "응답을 읽지 못함"을 받는다).

## 일시정지와 재개

| 사유 코드 | 언제 |
| --- | --- |
| `human-input` | 보내기·후속 지시 직전에 미제출 사람 입력이 있음 |
| `session-ended` | 진행 중인 태스크의 세션이 끝남 |
| `send-failed` | 보내기·후속 지시 실패(오류 코드는 기록에 남김) |
| `judge-failed` | 판단자 호출·파싱 실패 |
| `followup-limit` | 한 태스크의 후속 지시가 3번을 넘음 |
| `judge-stop` | 판단자가 `stop`을 고름(메시지를 함께 보임) |
| `task-busy` | 준비된 태스크가 이미 진행 중·검토 대기(사람이 따로 보냄) |
| `task-changed` | 진행 중인 태스크가 지워지거나 할 일로 되돌려짐 |
| `app-restarted` | 앱을 다시 켬. 실행 중이던 자동 진행은 모두 일시정지로 복원 |
| `user` | 사람이 일시정지를 누름 |

- **계속**: 현재 태스크가 검토 대기면 판단부터, 진행 중이면 턴 종료를 기다리고, 없거나 할 일이면 고르기부터 다시 한다.
- **끝내기**: 실행 상태와 기록을 지운다. 업무 상태는 그대로 둔다.
- 일시정지 중 판단자 호출이 끝나면 그 결과는 버린다.
- 사람은 언제든 진행자 터미널에 직접 입력할 수 있다. 사람이 프롬프트를 넣으면 그 턴도 끝날 때 판단자가 함께 본다.
- 사람이 현재 태스크를 완료로 바꾸면 다음 태스크로 넘어간다.

## 시작 조건

다음 중 하나라도 걸리면 시작 버튼을 막고 이유를 보여준다.

- 루트에 담당이 없거나, 선행 작업이 없거나, 완료됨.
- 담당 프로필이 보내기를 지원하지 않음(기존 보내기 차단 사유와 같다).
- 에이전트 관찰이 꺼져 있음. 턴 종료와 전사 경로를 훅으로 알기 때문이다.
- 플랜에 다른 캐릭터에게 배정된 미완료 태스크가 있음.
- 진행자에게 끝나지 않은(진행 중·일시정지) 다른 자동 진행이 있음(`auto-run-runner-busy`). 멈춘 실행의 현재 태스크와 섞이지 않게 진행자 한 명은 실행 하나만 가진다.

실행 중에는 진행자에게 사람이 다른 업무를 보내는 것을 막는다(`work-send-auto-run`).

## 저장

루트 업무의 `autoRun` 필드 하나에 둔다. 네이티브는 내용을 해석하지 않고 보존만 한다.

```ts
interface AutoRun {
  state: "running" | "paused" | "finished";
  judgeSessionId: string;      // 판단자 claude 세션 uuid
  judgeStarted: boolean;       // 첫 호출을 마쳤는지(--session-id vs --resume)
  judgedBodyHash?: string;     // 판단자에게 마지막으로 보낸 루트 본문의 해시
  currentId?: string;          // 진행 중인 태스크
  followUps: number;           // 현재 태스크에 넣은 후속 지시 수
  pauseReason?: string;        // 사유 코드
  pauseDetail?: string;        // 판단자 메시지·오류 코드
  costUsd: number;             // 판단자 누적 비용
  log: { at: number; kind: string; taskId?: string; text?: string }[]; // 최근 200건
  startedAt: number;
}
```

기록은 루트 상세 팝업에 시간순으로 보인다. 루트 본문에 덧붙이지 않는 이유는, 사람이 팝업에서 본문을 고치는 초안과 앱의 덧붙이기가 충돌하기 때문이다. 본문은 사람의 플랜 메모로만 남는다.

## IPC

| IPC | 동작 |
| --- | --- |
| `send_work_follow_up` | `{agentId, sessionId, text}`. 실행 중인 CLI에 bracketed paste + CR로 프롬프트 하나를 넣는다. 보내기와 같은 캐릭터별 상호배제·전환 소유권·사람 입력 검사를 쓴다. 성공하면 `{sessionId, submittedAt}` |
| `work_last_reply` | `{agentId, cli, cwd}`. 위 '마지막 응답 읽기'. 없으면 `null` |
| `auto_run_judge` | `{sessionId, resume, prompt, model?}`. 판단자 호출 1회. `{decision, message, note, costUsd?}` |

## 검증 (2026-10-15)

- `npx tsc --noEmit`, 프런트 전체 185개 파일·2,643개 통과. `autoRun.test.ts`: 계획 모으기·시작 차단, 판단자 프롬프트(첫 호출·메모 변경), 보내기 → next(인계 메모 전달) → followup → stop → 계속 → 마침 전체 흐름과 비용·기록, 미제출 입력에서 재시작하지 않고 멈춤, 판단자 첫 호출 실패 시 세션 id 교체, 후속 지시 중 사람 입력, 진행 중 수동 보내기 차단, 사람이 완료·할 일로 되돌림, 세션 종료, 앱 재시작 시 일시정지 복원.
- `cargo test` 전체 1,225개 통과. 후속 지시 입력(bracketed paste + CR, 교체된 세션·사람 입력·제어문자 거절), 마지막 응답 추출(서브에이전트 제외, 끝 보존), 판단자 인자·출력 파싱 단위 테스트.
- 실기(ignored 테스트): `real_claude_judge_resumes_the_same_session` — 설치된 claude 2.1.300으로 `--session-id` 뒤 `--resume`이 같은 세션을 이어 구조화 결정을 돌려줌. 수동 측정에서 두 번째 호출 입력 3,962토큰이 캐시로 읽혔다. `real_transcript_last_reply` — 실제 Claude 전사에서 마지막 턴 응답 전체를 뽑음.
- `npm run gui:shot -- --scenario workpanels`: 루트 카드 칩, 일시정지된 루트 팝업(판단자 메시지·비용·기록), 시작 전 팝업(차단 사유)을 확인했다.
- 남은 것: 설치 앱에서 실제 Claude·Codex 작업자로 여러 태스크 플랜을 끝까지 돌리기, 권한 다이얼로그 대기 중 동작, Windows 판단자 실행(`claude.exe`가 PATH에 있어야 한다. npm 설치의 `claude.cmd`만 있으면 `claude-not-found`).

## 하지 않는 것

- 여러 캐릭터에 걸친 병렬 진행. 진행자는 한 명이다.
- 판단자가 태스크를 추가하거나 순서를 바꾸는 것. 필요하면 `stop`으로 멈추고 사람이 고친다.
- 권한 다이얼로그 자동 승인.
- Codex 등 다른 CLI의 판단자. 작업자는 보내기가 지원하는 CLI를 모두 쓸 수 있다.
- 앱 재시작 뒤 자동 재개.
