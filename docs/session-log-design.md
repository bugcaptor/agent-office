# 세션 로그 & 학습자료 설계

터미널 세션에서 실제로 오간 내용을 **상시** 파일로 남기고(최대 30일), 그중 하나를
골라 **수동으로** 회고·학습용 자료(Markdown)를 만드는 기능의 정본 설계다.

관련 이슈: 세션 로그 보관 + 학습자료 생성.
관련 문서: `subsystem-a-sessions.md`(출력 파이프라인), `session-analytics-design.md`
(이벤트 시계열 — 이 문서와 **다른 데이터**다), `usage-design.md`.

---

## 1. 무엇을 왜

지금까지 이 앱이 남기는 것은 **메타데이터**뿐이었다.

| 기존 | 무엇 | 어디 |
| --- | --- | --- |
| `session-events/v1/<날짜>.jsonl` | 상태 전이·훅 이벤트(시각, 종류) | 분석 패널 |
| `session-times.jsonl` | 턴 시작/끝 시각 | 타임라인 |
| `diaries/<agentId>.jsonl` | LLM이 쓴 일기 한 문단 | 일기 다이얼로그 |

**대화·명령의 본문은 어디에도 남지 않았다.** 터미널 버퍼(xterm 스크롤백 5000줄,
데몬 링버퍼 512KB)에만 살다가 탭을 닫거나 앱을 끄면 사라진다. 회고하려면 그 본문이
필요하다. 그래서 PTY 출력을 상시 파일로 남긴다.

AI 대화와 일반 셸 작업을 **구분하지 않는다**. 둘 다 같은 PTY를 지나가므로 한 벌의
캡처로 둘 다 남는다 — `claude`를 띄운 탭이든 `npm test`를 돌린 탭이든 동일하다.

## 2. 결정 사항 (요약)

| 갈래 | 결정 | 근거 |
| --- | --- | --- |
| 저장 형식 | **정리된 텍스트만** (ANSI 제거·재그리기 축약) | 바로 읽히고, LLM에 그대로 먹일 수 있고, 용량이 작다 |
| 캡처 지점 | 앱의 output pump (`session/output.rs`) | PTY 원시 바이트가 배칭 전에 지나는 유일 지점. 브로커 v1/v2·입양 경로가 전부 여기로 수렴 |
| 생성 방식 | **수동 트리거**, 백그라운드 CLI(`claude -p`) | 캐릭터 터미널을 건드리지 않고, 세션이 꺼져 있어도 동작 |
| 보존 | **30일 + 전체 2GB** | 기간이 1차 기준, 용량은 폭주 안전판 |
| 옵트인 | 기본 **켜짐**(`sessionLogEnabled`) | 나중에 회고하려면 "그때 이미 켜져 있었어야" 한다 |

설정이 꺼져 있으면 기록 핸들 자체를 만들지 않는다 — 껐는데도 헤더(작업 폴더
경로 포함)만 든 파일이 세션마다 생기면 "끔"이 아니다. 세션이 도는 **중에** 끄면
원자 플래그로 즉시 멈추고, 다시 켜면 그 세션부터 이어서 기록한다.

## 3. 캡처: 원시 PTY → 읽을 수 있는 전사(transcript)

### 3.1 위치

```
PTY reader ─→ ReaderMsg::Data(bytes) ─→ output pump ─┬─→ OutputBatcher → Channel → xterm
                                                     └─→ TranscriptFilter → SessionLogWriter → 파일
```

`ReaderMsg::Restore`(입양 복원 화면 스냅샷)는 **기록하지 않는다**. 그것은 새 출력이
아니라 이미 기록된 내용의 화면 이미지다.

### 3.2 왜 필터가 필요한가

Claude Code(Ink)·Codex 같은 TUI는 화면을 지우고 다시 그리는 방식으로 동작한다.
원시 바이트를 그대로 `strip ANSI` 하면 스피너 프레임 하나하나가 전부 별도 줄로 남아
로그가 수십 배로 부풀고 읽을 수 없게 된다. 그래서 **작은 터미널 모델**을 두고,
"더 이상 다시 쓰일 수 없는 줄"만 파일로 확정(commit)한다.

### 3.3 모델

- `pending: VecDeque<String>` — 아직 덮어쓰일 수 있는 **라이브 영역**.
- `cursor: (row, col)` — `row`는 `pending` 안 인덱스.
- 라이브 영역 상한 `live_rows = max(rows * 2, 80)`.
  근거: 커서 되감기(`CSI n A`)는 화면 높이를 넘어설 수 없다. 화면 두 배보다 오래된
  줄은 원리상 다시 쓰일 수 없으므로 확정해도 안전하다.
- `pending.len() > live_rows`가 되면 앞에서 pop 해 파일로 확정한다.

### 3.4 처리하는 시퀀스

| 입력 | 처리 |
| --- | --- |
| 출력 가능 문자 | `pending[row]`의 `col` 위치에 **덮어쓰기**, `col += 1` |
| `\n` | `row += 1` (필요하면 새 줄 생성) |
| `\r` | `col = 0` |
| `\b` | `col -= 1` |
| `\t` | `col`을 다음 8의 배수로 |
| `CSI n A/B` (CUU/CUD) | `row ∓= n` (0 이하로는 클램프) |
| `CSI n C/D` (CUF/CUB) | `col ±= n` |
| `CSI n G` (CHA) | `col = n-1` |
| `CSI r;c H/f` (CUP) | 화면 하단 기준으로 환산: `row = pending.len()-rows + (r-1)` |
| `CSI n K` (EL) | 0=커서부터 끝 삭제, 1=처음부터 커서까지 공백, 2=줄 전체 비움 |
| `CSI 0 J` (ED) | 커서 아래 `pending` 절단 + 현재 줄 커서 이후 절단 ← **Ink 재그리기의 핵심** |
| `CSI 2 J` | 전체 확정(flush) 후 라이브 영역 리셋 |
| `CSI ?1049h/?47h` | **대체 화면 진입**: 확정 후 기록 중단, `[전체 화면 앱]` 마커 1줄 |
| `CSI ?1049l/?47l` | 대체 화면 이탈: 기록 재개 |
| SGR·OSC·DCS·그 외 | 무시(색·제목은 버린다) |

미지원 시퀀스는 **조용히 버린다** — 로그 품질 문제이지 정합성 문제가 아니다.

대체 화면(`vim`, `less`, `htop`)은 기록하지 않는다. 전면 재그리기 덩어리라 전사
가치가 없고 용량만 먹는다. 대신 마커 한 줄을 남겨 "여기서 뭔가 전체 화면 앱을
썼다"는 사실은 보존한다.

### 3.5 확정 시 후처리

- 우측 공백 제거. 전량 확정 시 꼬리의 빈 줄은 버린다(커서가 앉아 있던 자리).
- **연속 동일 줄 접기**: 같은 줄이 2회 이상 이어지면 한 줄 + `… (같은 줄 N회 반복)`.
  빈 줄은 접지 않는다 — 문단 구분이 사라지면 오히려 읽기 나쁘다.
- **시각 마커**: 직전 쓰기로부터 60초 이상 지났으면 `--- HH:MM:SS ---` 한 줄 삽입.
  회고할 때 "언제 무엇을"이 붙어야 쓸모가 있다.

### 3.6 확정 타이밍

라이브 영역 초과 외에, 다음에도 확정한다.

- **유휴 3초**: 출력이 멎으면 **끝에서 화면 한 장(rows)** 만 남기고 확정.
  (세션이 하루 종일 조용해도 마지막 대화가 파일에 남게 하려면 필요하다.)
- 세션 EOF / 앱 종료 / 대체 화면 진입 / `CSI 2J`: 전량 확정.

### 3.7 폭주 방어

기록 스레드로 가는 큐는 1024청크(≈8MiB)로 **막혀 있다**. 출력 펌프는 절대
블로킹하지 않고 `try_send`만 한다 — 큐가 차면 그 청크를 버리고 카운터를 올린다.
기록 스레드는 다음 쓰기에서 `… (출력이 너무 빨라 N개 조각을 건너뜀)`을 남긴다.
조용히 비는 로그보다 "여기서 빠졌다"가 낫다.

## 4. 저장소

```
<app_data>/session-logs/v1/
├── <agentId>/
│   ├── 20260725-140311-a1b2c3d4.log
│   └── 20260725-093015-9f8e7d6c.log
└── study/
    └── <agentId>-20260725-151200.md
```

- 한 세션 = 한 파일. 세션이 앱 재시작을 넘겨 살아남으면(입양) **같은 파일에 이어
  붙인다**(파일명 키가 sessionId라 자연히 이어진다).
- `agentId`는 경로 요소로 안전한지 검증한다(`diary_store.rs`의 규약 재사용) —
  실패하면 기록을 건너뛴다.
- 쓰기는 `O_APPEND` 단순 append. 원자 rename을 쓰지 않는 유일한 저장소다 —
  스트리밍이라 매번 파일 전체를 다시 쓸 수 없고, append는 부분 쓰기가 나도
  뒷부분만 잘릴 뿐 앞부분은 성하다.

### 4.1 헤더

파일 첫머리(생성 시 1회):

```
# agent-office session log v1
# agentId: term-3
# sessionId: a1b2c3d4-...
# cwd: /Users/me/dev/foo
# started: 2026-07-25T14:03:11+09:00
```

목록 UI는 헤더 앞 512바이트만 읽어 `cwd`/`started`를 얻는다(파일 전체를 읽지 않는다).

### 4.2 보존

부팅 직후 1회 + 6시간마다 GC:

1. **기간**: mtime이 30일보다 오래된 `.log`·`.md` 삭제.
2. **용량**: 남은 것의 총합이 2GB를 넘으면 **오래된 것부터** 2GB 아래로 내려갈 때까지
   삭제. 단 *지금 쓰이고 있는 파일*은 건드리지 않는다.
3. 빈 `<agentId>/` 디렉터리는 정리.

`shell_export::gc_dir`의 best-effort 관례를 따른다 — 실패는 무시하고 넘어간다.

## 5. 학습자료 생성

### 5.1 파이프라인

```
로그 파일 ─→ (앞 60% + 중략 + 뒤 40%로 120k자 캡)
          ─→ summarizer(SummaryPurpose::Study)
             claude -p "<학습자료 지시>" --model sonnet --output-format text
          ─→ study/<agentId>-<timestamp>.md
          ─→ 인앱 마크다운 뷰어(미리보기 모드)로 열기
```

`summarizer` 파이프라인을 재사용하되 목적별로 갈라지는 것을 **셋**으로 늘린다.

| 목적 | 입력 상한 | 타임아웃 | 모델 |
| --- | --- | --- | --- |
| `Label` | 2,000자 | 20초 | haiku |
| `Diary` | 2,000자 | 120초 | haiku |
| `Study` | **120,000자** | **300초** | **sonnet** |

지금은 `TEXT_MAX_CHARS`가 전역 상수이고 모델이 `claude.rs`에 하드코딩돼 있다.
둘 다 `SummaryPurpose`에서 갈라지도록 바꾼다(기존 두 목적의 동작은 그대로).

### 5.2 시스템 프롬프트 (요지)

한 세션의 전사를 받아 **회고·학습용 Markdown 문서**를 쓴다. 고정 섹션:

1. `## 한 줄 요약`
2. `## 무엇을 하려 했나` — 목표와 배경
3. `## 어떻게 진행됐나` — 시간 순 흐름, 실제 명령·파일명 포함
4. `## 막힌 지점과 해결` — 오류 메시지와 그것을 넘긴 방법 (**가장 중요한 섹션**)
5. `## 배울 점` — 다음에 같은 상황에서 바로 쓸 수 있는 형태로
6. `## 다시 해본다면` — 더 짧은 경로

규칙: 한국어, 로그에 실제로 있는 내용만(추측 금지), 명령·경로·오류는 원문 그대로
인용, 사과·머리말 금지.

### 5.3 비용

수동 트리거 전용이다. 자동 생성은 없다. 요약기 옵트인(`summarizerEnabled`)이 꺼져
있으면 생성 자체를 거절한다(일기와 동일 정책).

## 6. IPC 계약

```ts
listSessionLogs(agentId: string, offset: number, limit: number)
  : Promise<{ total: number; items: SessionLogItem[] }>   // 최신순

interface SessionLogItem {
  path: string;        // 절대 경로
  sessionId: string;
  startedAt: number;   // epoch ms (헤더 우선, 없으면 파일명)
  modifiedAt: number;
  bytes: number;
  cwd: string;
}

openSessionLog(path: string): Promise<void>           // 외부 에디터로 열기
generateStudyMaterial(agentId: string, path: string)
  : Promise<{ path: string; dir: string; fileName: string }>
```

`path`는 반드시 세션 로그 루트 아래인지 검증한다(경로 탈출 차단).
`generateStudyMaterial`이 돌려준 `dir`/`fileName`을 그대로
`markdownStore.openFile(dir, fileName, agentId)`에 넘기면 인앱 미리보기가 열린다.

## 7. UI

캐릭터 탭 우클릭 메뉴에 **`📜 세션 로그 보기`**를 `📔 일기 보기` 바로 아래 둔다.

```
┌ 📜 <캐릭터>의 세션 로그 ──────────────────┐
│ ● 07-25 14:03  12분  84KB  ~/dev/foo     │  ← 선택된 항목
│   07-25 09:30   3분   7KB  ~/dev/bar     │
│   …                                       │
│                          ‹ 2 / 7 ›        │  ← 10개씩 페이징
├───────────────────────────────────────────┤
│ [편집기로 열기]  [학습자료 만들기]         │  ← 선택 시에만 노출
└───────────────────────────────────────────┘
```

- 한 개를 고르면 하단에 동작 영역이 열린다(고르기 전엔 없음).
- `학습자료 만들기`는 진행 중 `만드는 중…`으로 비활성, 끝나면 인앱 뷰어로 전환.
- 요약기 옵트인이 꺼져 있으면 버튼은 비활성 + 안내 문구.

## 8. 필터를 눈으로 확인하는 법

실제 PTY 캡처를 필터에 통과시켜 보는 스모크 도구가 있다.

```sh
script -q /tmp/raw.txt sh -c '<확인하고 싶은 명령>'
cargo run --manifest-path src-tauri/Cargo.toml --example transcript_smoke -- /tmp/raw.txt
```

확인해 둔 것: 진행 표시줄(`\r`+`EL`) 5프레임 → 최종 한 줄로 접힘, `top` 출력 →
그대로 읽힘, `less` → 대체 화면 마커로 대체.

## 9. 알려진 한계

- **앱이 꺼진 동안의 출력**은 브로커 v2 데몬 링버퍼(512KB) 안에 남은 만큼만
  재생돼 기록된다. 그보다 많이 쏟아졌으면 가운데가 빈다. 완전 해결은 데몬 쪽
  기록이 필요하고, 그건 이 설계의 범위 밖이다.
- 필터는 터미널 에뮬레이터가 **아니다**. 스크롤 영역(`CSI r`), 줄 삽입/삭제
  (IL/DL), 이중폭 문자의 열 계산은 근사하거나 무시한다. 전사 품질이 조금
  나빠질 뿐 앱 동작에는 영향이 없다.
- 자동 줄바꿈(auto-wrap)을 흉내내지 않는다. 화면 폭보다 긴 줄은 파일에서도 한 줄로
  남는다 — 로그로는 오히려 낫다.
- 대체 화면 앱의 내용은 남지 않는다(§3.4).
