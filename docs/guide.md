## 주요 기능

- **에이전트 1명 = 터미널 세션 1개** — 캐릭터를 클릭하면 터미널이 열립니다. 닫아도 세션은 사라지지 않고 보존됩니다(보이기만 토글).
- **알림** — 에이전트가 응답을 기다리면 캐릭터 머리 위에 느낌표가 뜨고, 화면 오른쪽에 티커 알림이 쌓입니다. 클릭해 터미널을 열면 알림이 지워집니다.
- **머리 위 작업 라벨** — 각 캐릭터 위에 프로젝트·목표·현재 작업을 두 줄로 표시합니다. 로컬 CLI로 요약할 수도 있습니다(옵트인).
- **세션 시간 집계** — 프롬프트 입력부터 응답 완료까지, 세션별 작업/대기 시간을 패널로 보여줍니다(옵트인).
- **사용량 뱃지** — 하단 바에 Claude·Codex 구독 한도 사용률(`CL`·`CX`), Antigravity(agy) 한도 사용률(`AG`, agy를 설치·로그인했고 `agy -p /usage` 조회가 될 때만 — 조회가 안 되거나 값이 이상하면 표시하지 않음, 15분 간격), OpenCode Go 구독 사용률(`OC`, ⚙ 시스템 탭에 OpenCode API 키를 넣으면), OpenRouter 키의 오늘 사용액(`OR $0.29`, 요약 설정에 OpenRouter 키가 있으면) 중 **최근에 쓴 2개**를 표시합니다. 누르면 전부를 창별 사용률·기간별 금액·키 한도·리셋 시각까지 상세로 봅니다(API 키로 조회하는 OC·OR은 5분마다, 상세 창을 열면 바로 갱신).
- **캐릭터 일기** — 세션이 끝날 때 각 캐릭터가 자기 성격을 문체 삼아 작업 로그 겸 일기를 씁니다(옵트인). 탭 메뉴 → **일기 보기**로 열람합니다.
- **세션 로그 & 학습자료** — 터미널에서 오간 내용(AI 대화·명령·출력)을 읽을 수 있는 텍스트로 계속 기록합니다(기본 켜짐, 30일·2GB 자동 정리). 탭 메뉴 → **세션 로그 보기**에서 지난 세션을 골라 편집기로 열거나, 회고·학습용 문서(Markdown)로 정리시킬 수 있습니다(수동, 옵트인 CLI 사용).
- **작업 폴더 탐색** — 탭 메뉴 → **작업 폴더 보기**로 앱 안에서 파일·diff·커밋 기록을 보거나 시스템 파일 탐색기를 엽니다.
- **저장소 일괄 점검** — 오피스 배경의 서버 컴퓨터/랙을 누르면 작업 기록과 현재 프로필에서 수집한 Git 저장소를 한꺼번에 확인합니다. 커밋·push·pull·충돌 해결 등이 필요한 저장소가 위에, 정상 저장소가 아래에 표시되며 각 행에서 해당 폴더의 OS 터미널을 열 수 있습니다.
- **픽셀 아트 캐릭터** — 프로필을 만들면 시드 기반 픽셀 캐릭터가 자동 생성됩니다. 인간 외에 엘프·오크·로봇·슬라임 등 아키타입 8종을 지원하며, 직접 그린 스프라이트 업로드(크롭·배경 투명화)나 로컬 Codex CLI 이미지 생성으로 교체할 수 있습니다.
- **팀 토의** — 역할 카드를 맡은 팀원 최대 5명(사회자 포함)이 한 주제를 토의하고 결정 메모를 남깁니다. 참가자마다 전용 터미널 탭에서 읽기 전용 규칙을 받고 돌며, 쉬는 캐릭터는 오피스 회의실에 모입니다([팀 토의](#팀-토의)).
- **셸 캐릭터(로컬 LLM)** — 말로 시키면 LLM이 셸 명령 하나를 제안하고, 실행은 사람이 누릅니다([셸 캐릭터](#셸-캐릭터-로컬-llm)).
- **머신 연동(호스트·클라이언트)** — 같은 tailnet·LAN의 다른 컴퓨터 앱과 페어링해, 호스트 한 곳에서 여러 머신 캐릭터를 보고 조작하고 업무를 맡깁니다([머신 연동](#머신-연동-호스트클라이언트)).
- **사무실 연출** — 세션이 도는 동안 캐릭터는 자리에 앉아 일하고, 한가해지면 탕비실로 가 쉽니다. 밝음·미드나이트·벚꽃 테마 3종을 제공합니다.

## Claude / Codex 연동 (옵트인)

선택적 연동은 **전부 기본 꺼짐**입니다. 첫 실행 동의 화면이나 하단 ⚙ 설정에서 켤 수 있습니다.

- **작업 라벨 요약** — Claude Haiku 또는 Codex `gpt-5.4-mini` 중 하나를 골라, 프롬프트마다 목표/현재를 한 번에 요약합니다. 세션이 실제 작업을 시작하면 목표를 한 번 더 다듬습니다('이슈 40 해결' → 실제 목적으로 구체화).
- **캐릭터 일기** — 요약과 같은 CLI로 세션 종료 시 일기를 자동 생성합니다(수동 '일기 쓰기' 버튼도 그대로).
- **학습자료 만들기** — 세션 로그 하나를 같은 CLI(Claude는 Sonnet, Codex는 `gpt-5.4`)에 넘겨 회고용 문서로 정리합니다. 자동 실행은 없고, 메뉴에서 누를 때만 돕니다.
- **에이전트 관찰 (알림·시간측정)** — 새로 만드는 터미널에 `claude`/`codex`용 훅을 준비해, 알림과 시간측정을 켭니다. `codex resume --last`, 프로필의 시작 명령도 같은 셸 래퍼를 통과합니다.

주의사항:

- 호출은 **선택한 로컬 CLI 계정의 구독 사용량/크레딧을 소비**합니다. 실패해도 다른 provider·모델로 재시도하지 않습니다.
- Agent Office는 **전역 Claude/Codex 설정을 수정하거나 승인을 대신하지 않습니다.** Codex hook은 Codex `/hooks` 화면에서 직접 검토·신뢰해야 합니다. Windows에서 Claude 관찰 훅을 사용하려면 Claude Code 2.1.139 이상이 필요합니다.
- 관찰 래퍼는 Windows PowerShell·PowerShell 7·Git Bash·zsh를 지원합니다(WSL 제외). 설정 변경은 **새로 만드는 터미널부터** 적용됩니다.
- 연동이 꺼져 있거나 실패해도 세션 관리·캐릭터·테마 등 나머지 기능은 계속 동작합니다.

## CLI로 조종하기 (옵트인, 2단계 승인)

다른 AI나 스크립트가 실행 중인 Agent Office를 조종할 수 있습니다. 보안 표면이라 **2단계 옵트인**입니다(기본 꺼짐).

1. ⚙ 설정 → **CLI 제어**를 켠다 → 로컬(`127.0.0.1`) 제어 서버가 임의 포트로 뜹니다.
2. **CLI 제어 승인**을 눌러 토큰을 발급한다 → 이때만 토큰이 생기고, 그 전엔 모든 요청이 401입니다(**승인 취소**로 언제든 폐기).

이용하는 쪽은 **주소·포트·토큰을 몰라도 됩니다.** 같은 바이너리의 `ctl` 서브커맨드가 자동으로 찾습니다. `ctl`은 GUI를 띄우지 않고 요청 1건 보내고 종료합니다.

```bash
agent-office ctl status                      # 연결/승인 상태 점검
agent-office ctl list                        # 프로필 + 실행 중 세션
agent-office ctl create reviewer --cwd ~/proj
agent-office ctl send builder "npm test" --enter
agent-office ctl notifications builder --json
agent-office ctl dispose reviewer
agent-office ctl settings set typingSoundEnabled=false
```

전체 명령은 `agent-office ctl help`로 봅니다.

### 외부 에이전트에게 플랜 맡기기

다른 에이전트(컴퓨터 활용 에이전트, 스크립트)가 플랜을 만들어 자동 진행으로 돌리고, 끝나면 단계별 결과를 받을 수 있습니다. 터미널 출력은 중계하지 않습니다. 시작·재개·멈춤·끝내기와 `ask`는 승인 뒤에 나타나는 **CLI 자동 진행 허용**을 한 번 더 켜야 합니다. 상태 조회와 사람에게 넘기기는 이 설정 없이도 됩니다.

```bash
A=$(agent-office task "원인 파악" - <<'EOF'
로그인 세션 만료 뒤 재로그인이 실패한다.
EOF
)
R=$(agent-office task --plan --after "$A" --to 하나 "로그인 회귀 수정" - <<'EOF'
목표·제약·완료 기준
EOF
)
agent-office ctl autorun start "$R"
agent-office ctl autorun status "$R" --wait --timeout 3600 --json > status.json
case $? in
  0)  echo "끝남" ;;            # steps[].report 에 단계별 보고
  10) echo "조치 필요" ;;        # attention.reason / attention.actions 를 본다
  11) echo "아직 진행 중" ;;   # running·wrapping_up·waiting-usage(사용량 대기, 스스로 이어 감)     # 다시 기다린다
esac
```

- `task`는 앱 밖에서도 기본 데이터 폴더를 써서 동작합니다(CLI 제어가 꺼져 있어도 됨). 플랜이 업무 목록에 반영되기까지 몇 초 걸리므로 `ctl autorun start`가 `auto-run-no-plan`이면 잠시 뒤 다시 시도하세요. `task --show <id> --json`은 자동 진행 상태까지 JSON으로 보여 줍니다.
- `status`의 `state`는 `none`·`running`·`waiting-usage`·`paused`·`needs-human`·`finished`입니다. `needs-human`은 진행 중인 단계가 권한 승인이나 질문에 답을 기다리는 상태이고, `attention.detail`에 훅이 준 설명(도구·명령)이 들어갑니다.
- 멈추면 `attention.actions`가 다음 동작을 알려 줍니다. `answer`(`task --edit <root> --body -`로 플랜 메모에 답을 적기), `send`(`ctl send`로 직접 지시), `split`(단계를 더 잘게 나누기), `edit`(담당·상태 바로잡기), `create`(`ctl create`로 세션 다시 띄우기), `focus`(그 캐릭터를 앞으로 띄워 화면에서 처리), `resume`, `escalate`, `end`, `wait` 중에서 고릅니다.
- CLI 재개는 같은 단계에서 2번까지입니다. 그 뒤에는 `resume`이 빠지고 `ctl autorun escalate <rootId> "<사람에게 전할 말>"`로 넘겨야 합니다. 넘기면 자동 진행이 멈추고 OS 알림이 뜹니다. 사람이 멈춘 실행과 넘긴 실행은 사람만 이어 갈 수 있습니다.
- 권한 승인이나 질문을 설정한 시간(기본 10분)만큼 기다리면 자동 진행이 **승인 대기 시간 초과**로 멈춥니다. Agent Office는 승인을 대신 누르지 않습니다.
- 플랜 없이 한 번만 물을 때는 `ctl ask <agentId> "<프롬프트>" --timeout 600`을 씁니다. 실행 중인 세션에 입력하고, 턴이 끝나면 마지막 응답을 출력합니다. 터미널에 쓰다 만 사람 입력이 있으면 끼어들지 않고 거절합니다.
- 기다리는 명령(`autorun status --wait`, `ask`)의 종료 코드는 `0` 끝남, `10` 조치 필요, `11` 시간 초과입니다. `ctl state <agentId>`는 턴 상태(`working`·`needs-human`·`idle`·`ended`·`none`)만 바로 알려 줍니다.

### 에이전트·CLI에서 토의 열기

에이전트나 스크립트가 [팀 토의](#팀-토의)를 만들고 결과(결정 메모)를 받을 수 있습니다. 만든 토의는 **준비** 상태로 업무 패널에 생기고, 사람이 카드의 **시작**을 눌러 시작합니다.

```bash
D=$(agent-office task --discuss --moderator 하나 --with 둘 --with 셋 --role 셋=비판자 --rounds 3 "저장 형식을 바꿀까" - <<'EOF'
배경·선택지·제약
EOF
)
agent-office ctl discuss start "$D"        # 'CLI 자동 진행 허용'이 켜져 있을 때만
agent-office ctl discuss watch "$D" > live.ndjson &   # 바뀔 때마다 한 줄 JSON(중계용, 결론이 나면 끝남)
agent-office ctl discuss status "$D" --wait --timeout 3600
case $? in
  0)  agent-office ctl discuss memo "$D" ;;   # 결론 확인 대기(review)·끝남
  10) echo "조치 필요" ;;   # ready(시작 전)·waiting_user(사회자 질문)·paused
  11) echo "아직 진행 중" ;;   # running·wrapping_up·waiting-usage(사용량 대기, 스스로 이어 감)
esac
```

- `task --discuss`는 앱 밖에서도 동작합니다(CLI 제어가 꺼져 있어도 됨). 팀원은 이름이나 id로, 역할은 역할 이름이나 id로 지정합니다(`--role <팀원>=none`은 역할 없음). 지정하지 않으면 업무 패널에서 열 때와 같은 기본값(프로필 기본 역할, 역할 → 프로필 → claude 순의 CLI, 상한 4라운드·30분·$5)이 들어갑니다. 전체 옵션은 `task --discuss --help`로 봅니다.
- 토의가 업무 패널에 반영되기까지 몇 초 걸립니다. 그 사이 `status`의 `state`는 `pending`이고, `start`·`answer`는 반영될 때까지 잠시 기다립니다.
- `ctl discuss start`와 `ctl discuss answer <id> "<답>"`(사회자가 사용자에게 한 질문에 답하기)는 **CLI 자동 진행 허용**이 필요합니다. 목록(`discuss list`)·상태·결정 메모 조회는 이 설정 없이도 됩니다.
- `status`의 `participants[]`에는 참가자마다 `speaking`(지금 말하는 중), `speakingSince`(차례를 받은 시각), `last`(최근 공개 발언의 `at`·`round`·`kind`·앞 160자 `text`)가 들어갑니다. 시각은 epoch ms 절대값입니다. "몇 분 전"은 받는 쪽이 계산합니다. 경과를 응답에 넣으면 내용이 그대로여도 `rev`가 바뀌어 `--since` 대기가 쓸모없어지기 때문입니다.
- `discuss watch <id> [--timeout S]`는 상태가 바뀔 때마다(`rev`가 달라질 때마다) `status`와 같은 data를 한 줄 JSON으로 출력합니다. 다른 프로그램이 이 줄을 읽어 토의를 중계할 수 있습니다. 비용·`updatedAt`만 바뀌어도 한 줄이 나오므로, 받는 쪽은 필요한 필드만 비교하세요. 멈춤·질문 대기도 계속 보고, 결론이 나면(`review`·`finished`) 0, `--timeout`을 넘기면 11로 끝납니다. `--timeout`이 없으면 끝까지 봅니다. 발언 전문은 내보내지 않습니다.
- 결론 확인(결론 확인 대기 → 끝남)은 사람이 카드에서 합니다.

토의 역할(역할 카드)도 CLI로 보고 바꿀 수 있습니다. 앱이 띄운 에이전트 세션은 사용자가 역할을 추가·수정해 달라고 할 때만 씁니다.

```bash
agent-office task --roles                       # id·스탠스·이름·기본 CLI (--json도 됨)
R=$(agent-office task --role-add "보안 검토자" --stance critical \
      --perspective "공격 경로와 권한 경계를 본다" --criteria - --cli codex <<'EOF'
근거 없는 "안전함" 판정을 하지 않는다.
EOF
)
agent-office task --role-edit "보안 검토자" --stance devils_advocate --no-cli
agent-office task --role-delete "$R"
```

- 스탠스는 `moderator`(사회자 칸 전용)·`free`·`supportive`·`critical`·`devils_advocate`·`divergent`·`synthesizer`입니다. 역할은 이름이나 id로 가리키고, 이름은 겹칠 수 없습니다.
- 바꾸기는 수신함(`work-inbox/roles/`)에 요청을 남기고 앱이 몇 초 안에 역할 목록에 적용합니다. 그 전에도 `--roles`와 `task --discuss --role`은 남긴 요청을 반영해 보므로, 방금 만든 역할을 바로 토의에 쓸 수 있습니다. 규칙에 어긋난 요청은 `rejected/`로 옮겨집니다.
- 역할 목록 파일이 아직 없으면(앱이 프리셋 역할을 만들기 전) 앱이 프리셋을 만든 뒤에 적용합니다.
- 역할 목록 창이 열려 있는 동안에는 적용을 미루고, 창을 닫으면 저장된 목록 위에 적용합니다. 창에서 지운 역할을 고치는 요청은 거부됩니다.

## 폰·다른 PC에서 보기: 웹 상태판 (옵트인)

앱이 켜져 있는 동안 tailnet이나 LAN에 작은 웹 페이지를 띄워, 폰이나 다른 PC 브라우저에서 캐릭터 상태와 에이전트 대화 로그를 봅니다. 터미널 화면을 비추지 않습니다.

1. ⚙ 설정 → **제어** → **웹 상태판**을 켭니다. 네트워크(Tailscale만 / LAN만 / 둘 다)와 포트(기본 7788)를 고릅니다.
2. 나온 접속 주소 옆 **주소 복사**를 눌러 그 기기에서 엽니다. 주소에 토큰이 들어 있고, 페이지는 처음 열 때 토큰을 브라우저에 저장한 뒤 주소에서 지웁니다.

- **보기**: 캐릭터 목록은 답을 기다리는 캐릭터, 작업 중인 캐릭터 순으로 위에 오고 나머지는 최근 상태가 바뀐 순입니다. 캐릭터별 상태(작업 중·답을 기다림·입력 대기·꺼짐)와 터미널에 Claude·Codex·Antigravity가 떠 있으면 "Claude 실행 중" 표시, 작업 목표와 작업 폴더 이름, Claude·Codex·Antigravity 대화 로그(최신이 위, 에이전트 말은 캐릭터 얼굴과 함께 Markdown으로 그리고 사람 말에는 👤, 도구 호출·결과는 접혀 있음), 토의 진행·속기록, 구독 사용량. 대화 로그는 지금 세션 것만 보이고(새 세션이 열리면 이전 대화는 사라짐) 세션 처음부터 최근 2000개 항목까지 거슬러 보이며, 작업 도중 끼워 넣은 입력까지 사람 입력은 모두 보입니다.
- **목록 미리보기**: 작업 중이거나 답을 기다리는 캐릭터(일반 에이전트 포함)는 목록 카드에 대화 로그 최근 5줄이 한 줄씩 보이고 계속 갱신됩니다(최신이 위, 도구 결과는 그 호출 아래). **▾ 접기**로 접으면 "▸ 작업 중"처럼 상태 한 줄만 남습니다. 접은 것은 그 브라우저 탭에서 새로고침해도 유지되고, 그 캐릭터의 세션이 바뀌면 다시 펼쳐집니다. 턴이 끝나 입력 대기로 돌아가면 미리보기는 숨습니다. 업무 탭에서도 **진행 중** 업무 카드에 담당 캐릭터가 작업 중이거나 답을 기다리면 같은 미리보기가 붙고(접기 상태도 공유), 미리보기를 누르면 그 캐릭터의 대화 로그로 갑니다.
- **진행 중 업무**: 캐릭터가 Agent Office 업무를 **진행 중**이면 목록 카드·캐릭터 화면 머리·스플릿뷰 칸 머리(사이드 패널 포함)에 "📋 업무 진행 중"과 업무 제목이 붙습니다. 플랜 단계면 플랜 제목·지금 단계(예: 단계 3/5)·완료 수(2/5 완료)와 단계 칸 막대(완료는 채움, 지금 단계는 깜빡임)가, 자동 진행 중이면 **자동 진행**·**자동 진행 멈춤** 표시가 함께 나옵니다. 좁은 칸에서는 플랜 제목을 빼고 막대와 완료 수만 보입니다. 누르면 업무 탭의 그 업무로 갑니다. 진행 중 업무가 여럿이면 자동 진행이 지금 보낸 단계, 그다음 최근에 바뀐 업무를 보입니다.
- **스플릿뷰**: 목록 오른쪽 위 **스플릿뷰** 스위치(기본 꺼짐, 켠 것은 그 기기에 기억)를 켜면 작업 중·답을 기다리는 캐릭터마다 대화 로그 칸이 화면 폭에 맞춘 격자로 나란히 보입니다(읽기 전용, 칸 머리를 누르면 그 캐릭터 화면). 칸은 턴이 끝나도 남아 있다가 칸의 **완료**를 누르거나 그 캐릭터의 터미널 세션이 바뀌면 빠집니다. 완료로 내린 캐릭터가 다시 작업을 시작하면 칸이 다시 생깁니다(완료는 칸만 내리고 업무 상태는 바꾸지 않음). 나머지 캐릭터는 왼쪽 사이드 패널(**◀ 접기**로 숨김, 좁은 화면은 **☰ 다른 캐릭터** 버튼으로 여는 서랍)에 있고, 누르면 그 캐릭터 화면으로 갑니다.
- **머리 카드 접기**: 캐릭터 화면 머리 카드는 처음엔 프로필·이름·위치·상태만 보입니다. 오른쪽 ▾(또는 머리)를 누르면 목표·업무·제어 단추와 그 아래 **직접 입력**·**업무 보내기** 칸이 함께 펼쳐지고, 다시 누르면 접힙니다. 쓰던 글은 접어도 남고, 펼친 상태는 그 브라우저에 기억됩니다. 권한 요청·질문 카드는 접혀도 보입니다.
- **스크롤 중 이름 바**: 캐릭터 화면을 내려 머리 카드가 가려지면 상단 바 바로 밑에 이름·작업 위치·상태·추정 비용(턴 수)만 담은 한 줄 바가 붙습니다. 누르면 맨 위로 올라갑니다.
- **직접 입력**: 캐릭터 화면의 입력칸에 쓴 말을 업무 보드에 남기지 않고 지금 세션의 CLI에 바로 넣습니다. CLI가 턴을 마치고 입력을 기다리면 바로 넣습니다. Claude가 작업 중이면 기다리지 않고 바로 넣어 다음 도구 호출 뒤에 반영됩니다. 답을 기다리는 권한 요청·질문이 있거나 다른 CLI가 작업 중이면 버튼이 **대기열에 넣기**로 바뀌어 [보낼 대기열](#보낼-메시지-대기열)에 쌓습니다. 작업 중이면 **중단하고 바로 보내기**로 대기열을 건너뛰고 턴을 끊어 바로 넣을 수도 있습니다. 터미널이 셸 프롬프트에 있으면(재시작한 새 세션 등) 버튼이 **Claude 띄워 보내기**처럼 바뀌어, 업무 보내기와 같은 방법으로 머리 카드에서 고른 CLI를 띄우고 쓴 말을 첫 프롬프트로 넣습니다(OpenCode를 골랐으면 기본 CLI로).
- **지금 상태 줄**: 대화 로그 맨 위(최신 자리)에 에이전트가 지금 무엇을 하는지 보입니다. 작업 중이면 점이 움직이며 "생각 중… 1분 12초"(도구가 도는 중이면 "Bash 실행 중…"), 작업 중인데 터미널 출력이 20초 넘게 끊기면 멈춘 표식과 함께 "멈췄을 수 있습니다"(캐릭터 카드에도 **응답 없음** 칩), 턴이 끝났으면 "입력을 기다림"입니다. CLI는 작업하는 동안 스피너와 경과 시간을 계속 다시 그리므로, 출력이 끊겼다는 것은 멈췄다는 신호로 봅니다.
- **이 세션 추정 사용량**: 캐릭터 화면(일반 에이전트 포함) 대화 로그 위에 "이 세션 추정 사용량 · 토큰 11.7K CH(1.7M) · $3.45 · 12턴"이 보입니다. 앱 터미널 위 작업 바와 같은 숫자로, 공개 API 요율로 환산한 추정치입니다(구독제 실제 청구액이 아님). Antigravity(agy) 세션은 턴이 끝날 때 agy 대화 기록의 토큰으로 셈하고, Orchestrator는 같은 계열 Gemini 4 요율로 칩니다. 요율을 모르는 모델(예: GPT-OSS)은 비용에서 빠집니다. 설정 › 시스템의 세션 비용 표시를 끄면 웹에서도 사라집니다.
- **하단 사용량 바**: 어느 화면이든 맨 아래에 Claude·Codex(값이 있으면 Antigravity도) 구독 사용량(5시간·주간 %)이 늘 보입니다. 1분마다 갱신하고, 누르면 사용량 탭으로 갑니다.
- **업무 보내기**(접혀 있음, 펼친 상태는 기억): 캐릭터 화면에서 제목(과 내용)을 써서 그 캐릭터에게 바로 업무로 보냅니다. 터미널에 CLI나 다른 명령이 돌고 있으면 "보내면 터미널을 재시작하므로 지금 세션은 끊깁니다" 경고가 뜨고, **재시작하고 보내기**를 두 번 눌러야 보냅니다(앱 쪽 확인창은 뜨지 않음). 앱에 쓰다 만 입력이 있으면 거절합니다.
- **화면 테마**: 머리 오른쪽 버튼으로 **자동**(기기 설정을 따름) → **밝게** → **어둡게**를 돌아가며 고릅니다. 고른 것은 그 브라우저에 저장되어 다시 열어도 그대로입니다(앱 테마와는 따로).
- **데스크톱 알림·제목 대기 수**: 머리 오른쪽 **🔕 알림**을 눌러 켜면(브라우저가 알림 권한을 물음, 켠 것은 그 브라우저에 기억) 캐릭터가 답을 기다리게 되거나 턴이 끝날 때 데스크톱 알림이 옵니다. 그 상태판 화면을 보고 있을 땐 보내지 않고, 알림을 누르면 그 캐릭터 화면으로 갑니다. 브라우저 탭·앱 창 제목에는 답을 기다리는 캐릭터 수와 화면을 안 보는 동안 끝난 턴 수를 더해 "(3) 컴퓨터 이름 · Agent Office"처럼 띄웁니다(홈 화면 앱으로 설치했으면 아이콘 배지도). 끝난 턴은 화면을 다시 보거나 그 캐릭터를 열면 빠집니다. 화면이 숨어 있는 동안에도 10초쯤마다 상태를 받지만, 브라우저가 오래 숨은 탭의 타이머를 늦추면 알림도 늦어질 수 있습니다. 알림은 HTTPS 주소(또는 127.0.0.1)에서만 되고, 폰 브라우저는 대개 지원하지 않습니다.
- **머신 구역 접기**: 머신 연동 호스트에서는 캐릭터 목록(과 스플릿뷰 사이드 패널)이 이 머신·붙은 머신마다 구역으로 나뉩니다. 구역 머리를 누르면 그 머신 캐릭터를 접고 펴며, 접힌 구역에 답을 기다리는 캐릭터가 있으면 머리에 "답 기다림 N"이 붙습니다. 접은 것은 그 브라우저에 기억됩니다.
- **머리의 컴퓨터 이름**: 페이지 맨 위(와 브라우저 탭 제목)에 앱이 도는 컴퓨터 이름이 보여, 여러 기기의 상태판을 띄워 둬도 가려집니다(macOS는 공유 설정의 컴퓨터 이름).
- **일반 에이전트**: 캐릭터 목록 맨 위 🤖 카드입니다. 캐릭터 없이 지시만 쓰면 앱에 "일반 에이전트" 터미널 탭이 생기고(보던 탭은 바뀌지 않음) Claude·Codex가 그 지시로 시작합니다. 캐릭터 persona만 없을 뿐 `office-task`·`office-md` 안내와 관찰 훅은 캐릭터 세션과 똑같이 들어가므로, 업무·플랜·토의를 만들게 하는 식으로 Agent Office 자체를 원격으로 다룰 수 있습니다(만든 업무는 미배정). 작업 폴더는 홈과 캐릭터들의 작업 폴더 가운데 고릅니다. 한 칸만 있고, CLI가 턴을 마치고 입력을 기다리면 **이어서 보내기**로 같은 세션에 다음 지시를 넣습니다. 작업 중이거나 답을 기다리면 **대기열에 넣기**로 쌓아 두었다가 턴이 끝나면 이어 넣고, **새 세션으로 보내기**(두 번 눌러 확인)로 지금 세션을 끊고 새로 열 수도 있습니다. 지시는 업무 보드에 기록하지 않습니다. 앱을 끄면 이 세션도 끝납니다.
- **보낸 업무 완료**: 캐릭터 화면 위쪽에 그 캐릭터에게 보낸 업무 중 진행 중이거나 끝나 확인을 기다리는 업무가 보입니다. 항목을 누르면 **업무** 탭의 그 업무 상세로 바로 이동하고, **완료**를 누르면 업무가 완료로 옮겨지며 앱에 떠 있던 그 업무 팝업과 그 캐릭터의 알림 카드·배지도 내려갑니다.
- **업무(작업보드) 탭**: 데스크톱 업무 패널과 같은 캐릭터별 묶음·플랜 계층(진행도·접기·`▶` 시작)·완료 묶음(기본 최근 20건, `더 보기`로 전체 확장)을 웹에서도 그대로 관리합니다. 모바일은 목록→상세 전환, PC 넓은 화면은 좌측 보드·우측 상세 마스터-디테일로 보입니다. 업무 생성·수정(제목·전체 본문·담당·상태·CLI/모델/추론 강도·선행 작업·플랜 루트·자동 진행 한도)·삭제·순서 변경(드래그 또는 `↑`/`↓`), 보내기(CLI 실행 중이면 2단계 확인 후 재시작 전송), 자동 진행(시작·일시정지·계속/사용량 대기 건너뛰기·끝내기·진행 로그), 예약(추가·규칙 변경·켜기/끄기·삭제)을 모두 지원합니다. 진행 중 업무의 담당 캐릭터가 권한 요청·질문을 기다리면 카드·상세에 알림이 뜨고 눌러 담당 캐릭터 대화 로그로 바로 이동해 답할 수 있습니다.
- **이미지**: 대화 로그에 에이전트 대화 속 이미지(붙여 넣은 그림, 에이전트가 Read로 연 그림 파일, Codex가 본 스크린샷)가 썸네일로 보이고, 누르면 화면 가득 커집니다. 그림이 온 파일 경로(Read·view_image로 연 파일, 경로를 붙여 첨부한 그림, 스크린샷 도구가 저장한 파일)를 알 수 있으면 썸네일 아래에 늘 보입니다(대화 보기도 같음). 캐릭터마다 최근 60장(64MB)까지만 들고 있어 오래된 것은 "더 볼 수 없습니다"로 바뀝니다. 설정의 **대화 로그에 이미지 보이기**로 끕니다(기본 켜짐).
- **복사·다운로드**: 대화 메시지, 코드 블록, 도구 호출과 결과의 텍스트를 각각 복사할 수 있습니다. 이미지와 에이전트가 대화에서 링크한 작업 폴더 안의 파일(최대 24MB)은 접속 기기의 브라우저 다운로드 위치에 저장됩니다. 이미지 복사 버튼은 보안 연결에서 브라우저가 클립보드 쓰기를 허용할 때 동작합니다. 평문 HTTP에서는 이미지를 길게 누르거나 우클릭해서 복사하세요.
- **권한 요청·질문에 답하기(Claude)**: Claude가 권한을 묻거나(Bash·파일 수정 등) AskUserQuestion으로 선택지를 내면 캐릭터 화면 위에 카드가 뜹니다. 권한은 **허용**·**허용하고 다시 묻지 않기**(두 번 눌러 확인)·**거부**(사유를 쓰면 에이전트에게 전함), 질문은 선택지를 고르거나 직접 써서 **답 보내기**. 터미널을 웹으로 바꾸는 모드는 없습니다 — 같은 대화상자가 앱 터미널에도 그대로 떠 있고, 어느 쪽에서든 먼저 답한 것이 반영됩니다. 터미널에서 먼저 답하면 웹 카드는 다음 훅(도구 실행 끝·턴 끝)에 사라집니다. **웹에서 닫기**는 답하지 않고 웹 카드만 내립니다. 이 버전 앱에서 새로 시작한 Claude 세션부터 됩니다(훅이 세션 시작 때 들어감). Codex 승인 화면은 아직 "답을 기다림"으로만 보입니다. 앱 터미널 탭의 [대화 보기](#터미널-보기--대화-보기)에서도 같은 카드에 답할 수 있습니다.
- **간접 명령**: 직접 입력(대기열), 작업 중단(Esc)·Ctrl-C, 셸 프롬프트에서 Claude·Codex 실행, 터미널 재시작·이어하기·종료, 업무 보내기·완료, 토의 시작·사회자에게 답하기, Claude 권한 요청·질문에 답하기. 재시작·종료처럼 되돌리기 어려운 버튼은 한 번 더 눌러야 실행됩니다.
- 웹에서 명령이 들어오면 앱 화면 왼쪽 아래에 알림이 뜨고, 누가 보고 있으면 "🌐 웹 접속 n"이 보입니다.
- 고른 네트워크의 주소와 이 컴퓨터(127.0.0.1)에만 열립니다. Tailscale을 나중에 켜도 몇 초 안에 따라 붙습니다. 주소가 새어 나갔다면 **토큰 새로 만들기**로 기존 기기를 모두 끊습니다.
- **tailnet은 HTTPS**: Tailscale 주소는 `https://<기기>.<tailnet>.ts.net:<포트>`로 열립니다. 인증서는 앱이 `tailscale cert`로 받아 오므로(12시간마다 갱신 확인) Tailscale 관리 화면의 DNS에서 MagicDNS와 **HTTPS Certificates**를 켜 두어야 합니다. 꺼져 있거나 `tailscale` 명령이 없으면 예전처럼 HTTP로 열고 설정 화면에 이유를 보입니다. 예전 `http://100.x.y.z:<포트>` 주소로 열어도 HTTPS 주소로 넘어갑니다. 주소(origin)가 바뀌므로 처음 한 번은 토큰이 든 새 주소를 복사해 여세요.
- **LAN은 자체 서명 HTTPS**: LAN 주소는 `https://192.168.x.y:<포트>`로 열립니다. 앱이 처음 켤 때 이 컴퓨터만의 CA(10년)를 만들고, 그 CA로 지금 LAN IP를 담은 서버 인증서(397일, 만료 30일 전이나 IP가 바뀌면 다시 발급)를 씁니다. 처음 열면 브라우저가 경고하므로 설정 화면의 CA 지문과 인증서 정보의 SHA-256 지문이 같은지 확인하고 진행하세요. 경고 없이 쓰려면 그 기기에서 `https://<LAN 주소>:<포트>/ca.crt`를 열어 CA를 설치합니다(iOS는 설치 뒤 설정 › 일반 › 정보 › 인증서 신뢰 설정에서 켬). CA를 바꾸려면 데이터 폴더의 `web-dash-tls/lan-ca*.pem`을 지우고 웹 상태판을 껐다 켭니다. 예전 `http://` LAN 주소로 열어도 HTTPS로 넘어갑니다.
- 127.0.0.1만 평문 HTTP입니다(이 컴퓨터 안에서만 열림).

## 셸 캐릭터 (로컬 LLM)

CLI 없이 셸만 두는 캐릭터입니다. 주 용도는 폰·다른 PC의 [웹 상태판](#폰다른-pc에서-보기-웹-상태판-옵트인)에서 같은 셸 세션에 이어서 명령을 내리는 것입니다.

1. ⚙ 설정 → **셸 캐릭터**에서 OpenAI 호환 LLM 주소와 모델을 넣고 **연결 확인**을 누른 뒤 **저장**합니다. 위에서부터 차례로 시도하고, 꺼져 있거나(연결 3초) 응답이 없으면 다음 것으로 넘어갑니다. 예: 이 Mac의 Ollama `http://localhost:11434`, LM Studio `http://localhost:1234/v1`, 4090 Windows PC의 Ollama `http://<PC>.<tailnet>.ts.net:11434`(그 PC에서 `OLLAMA_HOST=0.0.0.0`으로 띄움). 명령 하나 만드는 일이라 14B급 코더 모델이면 충분합니다.
2. **로컬이 안 되면 클라우드로 폴백**(기본 꺼짐)을 켜면 로컬이 모두 실패했을 때 고른 provider(요약기와 같은 Claude·Codex·Gemini·OpenRouter 등)로 다시 시도합니다. 이때 요청과 최근 명령 출력이 클라우드로 갑니다. 모델을 비우면 그 provider의 라벨 요약 기본 모델을 씁니다.
3. 캐릭터 프로필 → 터미널에서 **셸 캐릭터**를 켜고 터미널을 재시작합니다. 셸 rc 뒤에 명령 경계 표식을 찍는 훅이 한 번 들어갑니다(zsh·bash 4.4+·PowerShell. fish·WSL은 표식 없이 프롬프트 여부만 봄).

- **웹**: 캐릭터 화면에 **말로 시키기** 칸이 있습니다. 쓰고 **명령 만들기**를 누르면 명령과 한 줄 설명이 담긴 제안 카드가 뜨고 **실행**·**수정**·**다시**·**취소** 중 고릅니다. 지우기·강제 푸시 같은 되돌리기 어려운 명령은 ⚠ 표시가 붙습니다(막지는 않음). `!`로 시작하면 LLM 없이 그 명령을 바로 실행합니다. 명령이 돌고 있거나 앱 터미널에 쓰다 만 입력이 있으면 실행을 거절합니다.
- **출력**: 터미널 화면을 비추지 않고 명령마다 블록(명령·종료 코드·출력·걸린 시간, 최신이 위, 블록당 최근 600줄·세션당 40개)으로 보입니다. 끝나면 결과를 한두 줄로 설명합니다(설정에서 끔, 출력이 없으면 LLM을 부르지 않음). 실행 중에는 출력 꼬리와 **중단(Ctrl-C)** 버튼이 보입니다. vim·top 같은 전체 화면 앱은 화면을 기록하지 않고 표시만 남깁니다.
- **앱**: 셸 캐릭터의 터미널 위에 입력줄이 생깁니다. 말로 쓰면 만든 명령을 터미널 입력줄에 채우고, Enter는 직접 누릅니다.
- 명령 제안에는 OS·셸 종류·현재 폴더와 최근 명령 3개의 출력이 맥락으로 들어갑니다. 대화는 기억하지 않습니다.

## 머신 연동 (호스트·클라이언트)

같은 tailnet이나 LAN에 있는 다른 컴퓨터의 Agent Office를 호스트 하나에 붙입니다. 호스트에서 다른 머신 캐릭터를 보고 조작하고, 업무를 맡겨 자동 진행할 수 있습니다.

1. **호스트**: ⚙ 설정 → **머신 연동**에서 **호스트**를 고릅니다. 클라이언트는 이 컴퓨터의 [웹 상태판](#폰다른-pc에서-보기-웹-상태판-옵트인) 서버로 붙으므로 제어 탭에서 웹 상태판도 켭니다. **페어링 코드 만들기**를 누르면 8자 코드(`ABCD-EFGH`)가 5분 동안 뜹니다. 한 번만 쓰고, 다섯 번 틀리면 버려집니다.
2. **클라이언트**: 같은 화면에서 **클라이언트**를 고르고, 호스트 화면에 보이는 주소(예: `https://192.168.0.5:7788`, tailnet은 `https://<호스트>.<tailnet>.ts.net:7788`)와 코드를 넣고 **페어링**을 누릅니다. 자동 발견은 없습니다.
3. 붙으면 클라이언트 화면 아래 왼쪽에 `🔗 <호스트>에 연결됨`, 호스트에는 `🔗 연동 기기 n`이 보입니다.

- 역할은 하나만 고릅니다. 클라이언트는 호스트 하나에만 붙고, 호스트는 다른 호스트에 붙지 못합니다. 페어링한 기기에는 권한 등급 없이 전부 허용합니다.
- LAN 주소는 페어링 때 호스트 앱의 CA 인증서를 고정하고 이후로는 그 CA만 믿습니다. 코드는 그대로 보내지 않고 클라이언트가 본 인증서 지문과 묶은 증명으로 주고받아, 가운데서 다른 인증서를 낸 쪽은 페어링하지 못합니다. tailnet 이름 주소는 공인 인증서로 확인하고, `http://`는 이 컴퓨터와 tailnet IP에만 씁니다.
- 끊기면 1·2·4…초(최대 60초) 간격으로 다시 붙습니다. 끊긴 동안 보낼 것은 쌓아 두었다가(앱을 다시 켜도 남음) 다시 붙으면 보냅니다. 같은 컴퓨터는 끊었다 붙거나 다시 페어링해도 같은 기기로 보입니다.
- 앱 버전과 별개인 **연동 프로토콜 버전**이 다르면 연결을 거부하고 어느 쪽을 업데이트할지 알려 줍니다. 호스트가 업데이트되면 10분 안에 저절로 다시 붙어 봅니다.
- 호스트의 **페어링된 기기** 목록에서 기기별로 **해제**하면 그 기기는 끊기고 다시 붙지 않습니다(다시 페어링해야 함).

### 다른 머신에 업무 맡기기

호스트의 업무 보드가 정본입니다. 클라이언트 머신의 업무 보드는 그대로 두고, 호스트에서 받은 업무만 맨 위 **호스트에서 받은 업무** 묶음에 따로 보입니다.

- 호스트의 업무 팝업 **담당 캐릭터**에서 다른 머신 캐릭터(머신 이름 묶음)를 고르면 **저장소** 칸이 나옵니다. git 원격 주소(`git@github.com:팀/저장소.git`, `github.com/팀/저장소` 모두 같게 봅니다)와 업무마다 하위 경로·브랜치·워크트리 여부를 정합니다. 비워 두면 그 캐릭터의 시작 폴더에서 일합니다.
- 클라이언트는 캐릭터 시작 폴더와 그 바로 아래 폴더, 작업 기록의 폴더에서 클론을 찾아 원격 주소 목록만 호스트에 알립니다(로컬 경로는 보내지 않음). 저장소 칸의 후보가 이 목록이고, 그 머신에 클론이 없으면 보내기·자동 진행 시작이 막힙니다. 그 머신에서도 받을 때 다시 확인해 없으면 이유와 함께 거절합니다.
- 브랜치를 정하면 그 브랜치에서 일합니다(없으면 만듭니다). 워크트리가 아니면 클론에 커밋하지 않은 변경이 있을 때 바꾸지 않고 거절합니다. 워크트리를 켜면 `<저장소>.worktrees/<업무 id>`에 업무마다 따로 만들고, 브랜치를 비우면 `office/<업무 id>`를 씁니다.
- 받은 업무는 그 폴더의 새 세션으로 시작합니다. 그 세션에서 `office-task`(업무 남기기·수정·완료·`--report`)는 저절로 호스트 보드로 갑니다. 다른 세션은 `office-task --host …`로 호스트 보드를, `--local …`로 이 머신 보드를 고릅니다. 호스트 보드 목록(`--host --list`)은 호스트가 보내 준 사본으로 봅니다. 호스트에서 완료한 받은 업무는 이 머신에서도 완료로 바뀝니다.
- 자동 진행은 호스트가 돌립니다. 플랜의 단계마다 담당(이 머신·다른 머신 캐릭터)을 따로 정할 수 있고, 그 머신이 올리는 턴 상태로 판단해 후속 지시만 내려보냅니다. 다른 머신 단계의 구독 사용량은 그 머신의 사용량으로 봅니다.
- 연결이 끊기면 진행 중인 턴은 그 머신에서 끝까지 돌고, 후속 지시·다음 단계는 **머신 대기**로 멈춥니다. 상태와 보고는 쌓아 두었다가 다시 붙으면 올리고, 자동 진행도 스스로 이어 갑니다.
- 받는 머신에서 **에이전트 관찰**이 켜져 있어야 합니다(턴 끝을 알아야 합니다). 웹 상태판 업무 탭은 다른 머신에 맡긴 업무를 보이고 보내고 진행하지만, 담당을 다른 머신 캐릭터로 바꾸는 것은 앱에서 합니다.

### 머신 간 팀 토의

호스트의 [팀 토의](#팀-토의)에 다른 머신 캐릭터를 참가자로 넣을 수 있습니다. 토의 열기 대화상자의 **팀원** 목록에서 이 머신 캐릭터 뒤에 `이름 · 머신`으로 보입니다(사회자 칸에도 고를 수 있습니다).

- 진행(누가 언제 말하나)과 결정 메모는 호스트가 맡습니다. 메모는 호스트 데이터 폴더에 저장되고, 결론 확인도 호스트에서 합니다.
- 다른 머신 참가자의 세션은 그 머신에서 열리고, 그 머신 화면에 `<이름> · <호스트> 토의` 탭으로 보입니다. 작업 폴더는 호스트 토의 폴더가 든 저장소(git 원격 주소)의 그 머신 클론이고, 하위 경로까지 따라갑니다. 클론이 없거나 토의 폴더가 저장소가 아니면 그 캐릭터의 시작 폴더(없으면 홈)를 읽습니다. 읽기만 하므로 브랜치를 바꾸거나 워크트리를 만들지 않습니다.
- 발언은 그 머신 세션에서 `office-discuss say`로 내거나 마지막 응답으로 받아 호스트로 올라옵니다. 호스트에는 그 세션 탭이 없습니다(터미널 화면은 보내지 않음).
- 참가자 머신이 끊겨 있으면 시작하지 않습니다. 진행 중에 끊기면 그 차례에서 **머신 대기**로 멈췄다가 다시 붙으면 스스로 이어 갑니다(그 머신 세션은 끊긴 동안에도 돕니다). 그 머신에서 탭을 닫으면 호스트 토의는 그 차례에서 멈춥니다.
- 비용 상한에는 다른 머신 참가자의 턴 토큰도 들어갑니다. 구독 사용량 대기는 이 머신 참가자만 봅니다.
- 회의실에는 다른 머신 참가자가 분신으로 앉고(누르면 원격 대화 보기), 회의록 보드·속기록·결정 메모·웹 상태판에는 `이름 · 머신`으로 나옵니다. 참가자 머신에서도 **에이전트 관찰**이 켜져 있어야 합니다.

### 머신 간 파일 보내기

붙은 머신끼리(클라이언트끼리는 호스트가 중계), 그리고 이 머신 캐릭터에게 파일·폴더를 보냅니다. 보내기만 있고 다른 머신 파일을 가져오는 기능은 없습니다.

1. **받는 머신**에서 ⚙ 설정 → **머신 연동** 아래 **파일 받기**를 켭니다(기본 꺼짐). 받은 파일 폴더는 기본 `~/Downloads/Agent Office`이고 바꿀 수 있습니다. 꺼 둔 머신은 받는 곳 목록에서 고를 수 없습니다.
2. 하단 바 **📁 파일**(돌고 있는 전송 수가 붙음), 터미널 탭 우클릭 **파일 보내기…**(그 캐릭터에게), 다른 머신 캐릭터 대화 창 머리의 **파일 보내기…**(그 머신 캐릭터에게)에서 받는 곳과 파일·폴더를 고르고 보냅니다.

- **저장 위치**: 머신에게 보내면 `<받은 파일 폴더>/<보낸 머신 이름>/`, 캐릭터에게 보내면 `<받은 파일 폴더>/<캐릭터 이름>/`에 둡니다(작업 폴더 밖이라 저장소를 더럽히지 않습니다). 수락을 묻지 않고 바로 저장하며 화면 아래 왼쪽에 알립니다. 같은 이름이 있으면 덮어쓰지 않고 `이름 (2).ext`로 둡니다. 폴더는 구조 그대로(빈 폴더 포함) 옮기고, 폴더 안의 심볼릭 링크는 건너뜁니다.
- **캐릭터에게 알리기**: 캐릭터에게 보낼 때 메모를 쓰거나 **세션에 저장 위치 알리기**를 켜면, 그 캐릭터 세션의 보낼 대기열에 "보낸 곳·저장한 절대 경로·메모"를 넣습니다(턴이 끝나면 들어가고, Claude가 작업 중이면 다음 도구 호출 뒤에 반영).
- **크기·검증**: 크기 상한은 없습니다. 4MB씩 보내며, 보내는 쪽이 만든 SHA-256과 맞춰 본 뒤에야 제자리로 옮깁니다. 받는 쪽은 시작할 때 디스크 여유를 보고 모자라면 거절합니다.
- **끊김**: 시작할 때 받는 머신이 끊겨 있으면 거절합니다. 보내는 도중 끊기거나 앱이 꺼지면 **멈춤**으로 두고, 기록의 **이어 보내기**로 받은 데까지 이어서 보냅니다(원본 파일이 그사이 바뀌었으면 다시 보내야 합니다).
- **에이전트**: 연동이나 파일 받기가 켜진 머신의 세션에는 `office-file` 안내가 들어갑니다. `office-file targets`(받는 곳과 받기 상태), `office-file send <머신|캐릭터|캐릭터@머신> <경로>... [--note "메모"] [--notify] [--wait]`, `office-file list|status <id>|resume <id>|cancel <id>`. 사람이나 업무가 시킬 때만 보내도록 안내합니다. 외부 스크립트는 `agent-office ctl file …`(같은 하위 명령, [CLI 제어](#cli로-조종하기-옵트인-2단계-승인) 승인 필요)을 씁니다.
- **웹 상태판**: **파일** 탭에서 받는 곳을 골라 접속한 기기(폰·PC)의 파일을 올려 보내거나, **머신에서 고르기**로 그 머신의 받은 파일·캐릭터 작업 폴더를 훑어 골라 보냅니다(호스트는 붙은 머신 것도 고를 수 있습니다). 보낸·받은 기록의 진행률·취소·이어 보내기와 받은 파일 내려받기도 됩니다.
- 보낸·받은 기록은 머신마다 최근 200건을 둡니다(받은 파일 자체는 지우지 않습니다).

### 에이전트끼리 조회·대화

에이전트 세션이 이 머신과 연동한 머신(클라이언트끼리는 호스트가 중계)의 다른 캐릭터 상태를 보고, 말을 걸어 답을 받습니다. 사람이 보는 화면은 따로 없고, 주고받은 글은 양쪽 세션 대화에 남습니다.

1. ⚙ 설정 → **머신 연동** 아래 **에이전트끼리 대화**를 켭니다(기본 꺼짐, 머신마다). 연동이 꺼져 있어도 이 머신 캐릭터끼리 씁니다. 꺼 둔 머신의 캐릭터에게는 닿지 않고, 그 머신 세션에는 안내가 실리지 않습니다. 새로 띄운 세션부터 적용됩니다.
2. 켠 머신의 세션에는 `office-peer` 안내가 들어갑니다. 에이전트는 사람이 시키지 않아도 필요하면 스스로 말을 겁니다.

- `office-peer agents`: 모든 캐릭터와 상태(입력 대기·작업 중·사람 대기·세션 없음, 대기열·권한 요청 수). 끊긴 머신·대화를 끈 머신도 표시합니다.
- `office-peer status <캐릭터>`·`log <캐릭터> [--turns n]`: 한 캐릭터의 자세한 상태와 최근 대화(사람 말·에이전트 말만).
- `office-peer ask <캐릭터> "메시지"`: 상대 세션 보낼 대기열에 `[Agent Office · message <id> from 이름@머신]`으로 넣습니다(턴이 끝나면, Claude가 작업 중이면 다음 도구 호출 뒤). 받은 에이전트가 `office-peer reply <id> "답"`을 실행해야 답이 됩니다. 보낸 쪽은 기본 100초(`--wait`로 최대 600초) 기다리고, 넘기면 종료 코드 8로 끝난 뒤 늦게 온 답을 보낸 세션에 넣습니다. `--no-wait`는 바로 끝냅니다. 긴 글은 `-`로 표준 입력에서 읽습니다.
- `office-peer launch|resume|interrupt <캐릭터>`, `unqueue <캐릭터> <대기열 id>`: 세션 띄우기·이어하기·중단·대기열 빼기. 권한 요청 답·세션 닫기는 하지 않습니다.
- `office-peer threads`: 이 머신이 끼었던 최근 대화(최근 200건)와 답.
- **상한**: 에이전트마다 시간당 30건, 같은 상대에게 시간당 10건. 답을 기다리게 한 상대에게 되물으면 먼저 답하라고 돌려보내고, 답하려고 또 묻는 깊이는 3단계까지입니다.
- `<캐릭터>`는 이름이나 `이름@머신`입니다. 상대 머신이 끊겨 있거나 대화를 껐으면 바로 실패하고 이유를 알려 줍니다.

## 사용 팁

### 저장소 일괄 점검

오피스 배경의 서버 컴퓨터 또는 서버 랙을 클릭하세요. 과거 세션 작업 기록의 cwd와 현재 프로필의 시작 폴더를 바탕으로 저장소를 찾아 점검합니다. 같은 저장소 안의 여러 하위 폴더에서 일했어도 한 행으로 합쳐집니다.

목록은 충돌·분기(diverged)·커밋·push·pull처럼 **조치할 것이 있는 저장소**, 조회 불가나 upstream 미설정처럼 **확인이 필요한 저장소**, **clean 저장소** 순입니다. 같은 그룹에서는 최근 작업한 저장소가 먼저 나옵니다. 행의 **OS 터미널로 열기**를 누르면 그 저장소의 최상위 폴더에서 외부 터미널이 열립니다. 새 탭 지원 범위는 아래 [외부 OS 터미널 열기](#외부-os-터미널-열기)와 같습니다.

점검은 자동으로 `fetch`하지 않습니다. push/pull 상태는 마지막으로 로컬에 받아 둔 remote-tracking 정보 기준이므로, 원격 서버의 최신 상태가 필요하면 터미널에서 직접 `git fetch`한 뒤 다시 점검하세요.

### 업무 수신함

업무 패널을 켜면 앱이 띄운 에이전트 세션에 "다음 할 일 남기기" 안내가 덧붙습니다. 에이전트에게 "이건 다음 할 일로 남겨 줘"라고 하면 업무 목록에 할 일 카드가 생깁니다(기본 담당은 그 캐릭터). 보내기는 직접 누르거나 [예약](#예약)을 걸어 정한 시각에 보냅니다.

"이 작업을 단계별 태스크로 나눠 줘"처럼 부탁하면 에이전트가 선행 작업을 걸어 순서 있는 태스크로 남기고, 목표와 플랜 메모만 담은 플랜 루트를 마지막에 따로 만듭니다(아래 [자동 진행](#자동-진행)). 카드를 눌러 여는 팝업의 **선행 작업**에서 직접 걸거나 뺄 수도 있습니다. 선행 작업이 모두 완료되기 전에는 카드에 대기 표시가 나오고 보내기가 막힙니다.

에이전트에게 "그 태스크 완료 처리해 줘"라고 하면 에이전트가 태스크를 완료로 옮깁니다. 에이전트는 이렇게 지시받았을 때만 완료하고, 스스로 끝났다고 판단해 완료하지는 않습니다. 완료되면 그 태스크를 기다리던 후속 태스크의 대기가 풀립니다.

에이전트는 태스크를 고치거나 지울 수도 있습니다. "그 태스크 제목을 바꾸고 검토 대기로 옮겨 줘", "빌드 태스크가 테스트 다음에 오게 순서를 바꿔 줘", "그 태스크는 지워 줘"처럼 부탁하면 제목·본문·담당·상태·선행 작업을 바꾸거나 태스크를 지웁니다. 지운 태스크를 기다리던 후속 태스크는 그 선행만 풀립니다. 삭제도 완료처럼 지시받았을 때만 합니다.

#### 자동 진행

선행 작업 사슬의 맨 끝 태스크(루트)는 목록에서 **플랜** 칩을 달고, 그 태스크가 기다리는 태스크들을 아래에 들여 보여 줍니다. 플랜 안에서 경고색 대기 표시가 없는 태스크가 지금 할 차례입니다. 루트 카드의 ▶나 루트를 열었을 때 보이는 **자동 진행** 영역에서 시작합니다. **자동 진행 시작**을 누르면 루트가 기다리는 태스크를 순서대로 진행합니다. 각 태스크는 그 태스크의 담당 캐릭터가, 담당이 없으면 루트의 담당 캐릭터가 맡습니다(다른 머신 캐릭터도 됩니다 — [다른 머신에 업무 맡기기](#다른-머신에-업무-맡기기)).

- 루트가 **플랜 루트**(플랜 메모 전용)이면 루트 자체는 실행하지 않습니다. 기다리는 태스크를 모두 마치면 루트를 검토 대기로 옮깁니다. 이때 검토 대기는 남은 작업이 없다는 뜻입니다. 에이전트에게 플랜을 맡기면 단계 태스크를 먼저 만들고, 마지막에 `office-task --plan`으로 플랜 루트(제목은 목표, 본문은 플랜 메모)를 만듭니다. 직접 만들 때는 태스크 팝업의 **플랜 루트 (플랜 메모 전용)**를 켭니다. 기다리는 태스크가 있을 때만 이 칸이 보입니다. 플랜 루트는 **보내기**로 보낼 수 없습니다.
- 플랜 루트가 아니면 루트도 일이 있는 태스크로 봅니다. 그래서 기다리는 태스크를 마친 뒤 루트도 마지막 단계로 보냅니다. 판단자가 받아들이면 루트를 검토 대기로 옮기고 끝납니다. 이런 루트 카드에는 **루트 작업 포함**이 붙고, 진행도에도 루트가 들어갑니다. 루트만 남았는데 진행 중이거나 검토 대기면 시작할 수 없습니다. 다시 진행하려면 할 일로 되돌리세요.
- 카드의 **자동 진행 상세 설정**에서 최대 후속 지시 횟수와 승인·질문 대기 시간을 바꾼 뒤 **저장**을 누르세요. 루트에 지정한 값은 플랜 전체에 적용되고, 태스크에 따로 지정한 항목은 그 단계에서 우선합니다. 값을 지우면 다시 상속합니다. 양쪽이 모두 비어 있으면 후속 지시는 3회, 대기 시간은 10분입니다. 후속 지시를 0회로 설정하면 판단자가 추가 작업을 요청할 때 멈춥니다. CLI에서는 생성 또는 수정 시 `--max-follow-ups`와 `--permission-wait-minutes`를 사용합니다. 예를 들어 `office-task --edit <id> --max-follow-ups 5 --permission-wait-minutes inherit`는 후속 지시를 5회로 바꾸고 대기 시간은 다시 상속합니다.
- 태스크마다 CLI를 새로 시작합니다. 대신 루트 본문(플랜 메모)과 앞 태스크의 인계 메모를 프롬프트 뒤에 붙여 줍니다.
- 턴이 끝나면 판단자(`claude -p`)가 마지막 응답을 읽고 다음 태스크로 넘길지, 같은 세션에 후속 지시를 넣을지, 멈추고 사람에게 물을지 정합니다. 판단자는 실행마다 한 대화를 이어 가므로 앞의 판단을 기억하고 프롬프트 캐시도 재사용합니다. 판단자에게는 도구가 없습니다.
- 진행 중에 루트 본문을 고치면 다음 판단부터 반영됩니다. 터미널에 직접 입력해도 자동 진행은 멈추지 않습니다(멈추려면 **일시정지**를 누르세요). 쓰다 만 입력이 있으면 그 위에 후속 지시를 넣지 않고 잠시 기다렸다가 다시 넣습니다. 2분 넘게 그대로면 그 표시를 풀고 넣습니다. 다음 태스크로 넘어갈 때는 터미널을 새 세션으로 바꾸므로 쓰다 만 입력도 함께 사라집니다. 미뤄 둔 후속 지시가 있는 동안 사람이 직접 지시해 새 턴을 돌리면, 그 지시는 버리고 그 턴이 끝난 뒤 다시 판단합니다.
- 권한 승인처럼 사람이 눌러야 하는 것은 지금처럼 카드가 강조되고, 처리하면 이어서 진행합니다.
- 멈춘 이유와 기록·판단자 비용은 루트 팝업에 보입니다. **계속**으로 이어 가고, **끝내기**는 진행 기록만 지웁니다(업무 상태는 그대로).
- 루트를 완료로 바꾸면 자동 진행도 끝납니다. 한 캐릭터는 끝나지 않은 자동 진행을 하나만 가지므로(루트 담당이든 단계 담당이든), 다른 플랜이 막히면 시작 버튼 옆 안내에 붙잡고 있는 플랜 이름과 **그 플랜 열기**가 보입니다.
- **에이전트 관찰**이 켜져 있어야 하고, 판단자는 로컬 `claude` CLI 계정의 사용량을 씁니다. 루트의 업무 에이전트가 Claude면 그 모델로 판단합니다.
- **사용량 대기**(기본 켜짐, 자동 진행 영역의 체크박스) — 태스크·후속 지시·판단자를 보내기 전마다 Claude·Codex 구독 한도 창이 버틸지 예측합니다. 사용률(%)만 보지 않고 훅이 주는 턴별 토큰을 API 요율 기준 비용으로 셉니다. 마지막 조회 뒤 쓴 양을 더해 지금 사용률을 추정하고, 끝난 태스크들의 실제 비용(상위 75%)으로 다음 태스크가 쓸 양을 잡고, 창마다 사용률 변화에서 배운 "비용 대비 %p" 비율로 %로 바꿉니다. 태스크 도중 창이 리셋되면 리셋 전 몫만 셉니다.
  - 한도 95%를 넘길 것 같으면 보내지 않고 카드에 **사용량 대기**를 띄웁니다. 그 창의 리셋 시각까지 기다렸다가 사용량을 새로 받아 스스로 이어 갑니다. 그 전에 조회값이 넉넉해지면 일찍 이어 갑니다. 후속 지시를 미뤘으면 다시 판단하지 않고 그 지시를 보냅니다.
  - 기다리는 동안 **기다리지 않고 계속**은 검사를 한 번 건너뛰고, **일시정지**는 스스로 이어 가지 않게 멈춥니다. 앱을 다시 켜도 대기는 이어집니다.
  - 끝난 태스크가 2개 쌓이고 비율을 배우기 전에도 사용률이 95%에 닿으면 기다렸다가 리셋 뒤 이어 갑니다. 다만 그때는 마지막 조회 뒤 쓴 양을 더하지 못합니다. 학습값은 이 기기에 남습니다.
  - 요금제가 바뀌면 조회값의 요금제 이름이 바뀌는 순간 그 구독의 비율을 버리고 다시 배웁니다. 이름이 그대로인데 한도가 바뀌면, 큰 표본이 같은 방향으로 두 번 연달아 비율과 2배 넘게 어긋날 때 옛 비율을 버립니다. 태스크 표본은 비용 단위라 요금제와 무관하게 계속 씁니다.
  - 앱이 거의 쓰지 않는 사이 오른 사용률(다른 터미널·웹)은 비율에 넣지 않습니다. 앱과 앱 밖 사용이 섞인 구간은 비율을 조금 키워 예측이 일찍 기다리는 쪽으로 기웁니다. 사용량 창이 없는 CLI(agy·kilo·pi)는 판단자가 쓰는 Claude 창만 봅니다.

#### 예약

태스크 팝업의 **예약** 영역에서 **예약 추가**를 누르고 반복(한 번·일정 간격·매일·매주)과 시각을 고른 뒤 **저장하고 켜기**를 누르세요. 시각은 이 컴퓨터의 시간대 기준입니다. 카드에는 다음 실행 시각이 붙습니다.

- **한 번** 예약은 정한 시각에 그 태스크 자체를 담당 캐릭터에게 보내고 예약을 지웁니다. 선행 작업이 있는 태스크(플랜 루트)면 자동 진행을 시작합니다.
- **반복** 예약(일정 간격·매일·매주)을 걸면 그 태스크는 템플릿이 됩니다. 회차마다 새 카드로 복사해 실행하고, 복사본에는 **예약 회차**가 붙습니다. 플랜 루트면 루트와 단계를 모두 복사해 자동 진행으로 돌립니다. 템플릿과 그 단계는 직접 보내거나 자동 진행할 수 없습니다.
- 간격은 5분에서 30일까지입니다. 일정 간격은 처음 켠 때부터 세고, 실행이 늦어져도 정해 둔 박자를 지킵니다.
- 앱이 켜져 있고 업무 패널과 **에이전트 관찰**이 켜져 있을 때만 예약을 실행합니다. 앱이 꺼져 있었거나 잠자기 중이라 예정 시각을 5분 넘게 놓친 회차는 실행하지 않고 건너뜁니다. 다음 경우에도 건너뜁니다. 건너뛰면 OS 알림이 뜨고(같은 이유가 이어지면 처음 한 번만) 예약 영역에 이유가 남습니다.
  - 지난 회차가 아직 할 일·진행 중이거나 자동 진행이 끝나지 않았을 때
  - 담당 캐릭터의 터미널에 CLI가 떠 있을 때(쉬는 중이어도). 보내면 그 CLI를 새 세션으로 다시 띄워 나누던 대화가 끊기기 때문입니다. 터미널이 없거나 셸 프롬프트일 때만 보냅니다. 예약을 걸 캐릭터는 CLI를 종료해 두세요.
  - 터미널에 쓰다 만 입력이 있을 때, 퇴근했거나 다른 자동 진행을 쥐고 있을 때
  - 보내기를 시작하지 못했을 때(시작하지 못한 복사본은 지웁니다)
- 플랜 예약은 첫 단계를 이렇게 보낸 뒤부터 보통 자동 진행처럼 단계마다 새 세션으로 진행합니다.
- 태스크를 완료로 바꾸면 예약이 꺼집니다. **끄기**로 잠시 멈추고 **켜기**로 다시 켭니다.
- 에이전트나 스크립트도 `office-task --at "2026-11-20 09:00"`(한 번)이나 `--every <규칙>`(`30m`·`2h`·`1d`·`daily@09:00`·`mon,wed@09:00`·`weekdays@09:00`)로 예약을 걸 수 있습니다. 수정은 `--edit <id> --every …`, 지우기는 `--no-schedule`입니다. 다만 이렇게 만들거나 바꾼 예약은 **꺼진 채로** 생기므로, 사람이 팝업에서 **켜기**를 눌러야 실행됩니다. 켜진 예약의 제목·본문·담당·선행 작업(플랜 단계 포함)을 `office-task`·수신함으로 바꾸거나, 앱이 켜진 동안 업무 파일을 직접 고쳐 바꿔도 예약이 꺼집니다. 사람이 확인하지 않은 내용이 실행되지 않게 하려는 것입니다.

#### 태스크 대화·ID 복사

카드를 눌러 연 팝업 머리의 ID 옆 ⧉ 버튼은 태스크 ID만 클립보드에 복사합니다. 에이전트에게 "태스크 `<ID>`를 봐 줘"처럼 가리킬 때 씁니다. 태스크가 어떤 상태인지 묻고 싶으면 팝업 아래쪽 **대화**(자동 진행 중이면 루트 팝업의 **현재 태스크에 대해 대화**)를 누르세요. 그 태스크의 본문·플랜·진행 기록·작업자 보고를 첫 프롬프트로 받은 새 CLI 세션이 터미널에 말풍선 탭으로 열립니다. 캐릭터와 상관없는 세션이라 자동 진행과 업무 상태를 건드리지 않고, 탭을 닫으면 세션도 끝납니다(동시에 4개까지).

#### 다른 프로그램에서 할 일 남기기

다른 프로그램(cron, 스크립트, 다른 도구)도 같은 폴더에 파일을 넣어 할 일을 남길 수 있습니다.

| OS | 수신함 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/com.bugcaptor.agent-office/work-inbox/` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/com.bugcaptor.agent-office/work-inbox/` |
| Windows | `%APPDATA%\com.bugcaptor.agent-office\work-inbox\` |

파일 하나가 할 일 하나입니다. UTF-8 `.md`, 64 KiB까지. 첫 줄(`# ` 생략 가능)이 제목, 나머지가 본문입니다. 담당 캐릭터는 선택 frontmatter의 `assignee`(이름 또는 id)로, 업무 id는 `id`로, 선행 작업은 `after`(쉼표로 구분한 업무 id)로, 예약은 `schedule`(`at 2026-11-20 09:00`·`every 30m`·`daily 09:00`·`weekly mon,wed 09:00`, 꺼진 채로 생김)로 정합니다. `done: <업무 id>`만 담은 파일은 그 업무를 완료로 바꿉니다. 쓰다 만 파일을 읽지 않도록 `.`으로 시작하는 임시 이름으로 쓴 뒤 `.md`로 바꾸세요.

```bash
inbox="$HOME/Library/Application Support/com.bugcaptor.agent-office/work-inbox"
name="$(date -u +%Y%m%dT%H%M%SZ)-$RANDOM.md"
printf -- '---\nassignee: 하나\n---\n# 로그인 회귀 테스트 추가\n세션 만료 뒤 재로그인 흐름이 없다.\n' > "$inbox/.$name.tmp"
mv "$inbox/.$name.tmp" "$inbox/$name"
```

업무 패널이 켜져 있으면 3초 안에 카드가 생기고 파일은 지워집니다. 형식이 틀렸거나 반영할 수 없는 파일(이미 있는 업무 id에 다른 내용, 없는 업무 완료)은 `work-inbox/rejected/`로 옮겨지고 옆의 `.error` 파일에 사유가 남습니다. 모르는 담당이나 없는 선행 작업은 빼고 카드를 만든 뒤 `work-inbox/warnings.log`에 한 줄 남깁니다.

안내를 덧붙일 수 없는 환경(예: Windows의 `agy`처럼 훅을 설치하지 않는 CLI)에서는 앱이 세션에 넣어 주는 `AGENT_OFFICE_TASK`(명령 경로)만 받습니다. 프로젝트 `AGENTS.md`에 한 줄 적어 두면 같은 방식으로 쓸 수 있습니다. (macOS·Linux의 `agy`는 전역 `~/.gemini/config/hooks.json`의 `SessionStart` 훅으로 Claude·Codex와 같이 캐릭터 성격과 `office-task`·`office-md` 안내를 받습니다.)

```markdown
- 나중에 할 후속 작업은 `"$AGENT_OFFICE_TASK" "제목" - <<'EOF'` … `EOF` 로 Agent Office 업무 목록에 남긴다(본문에 맥락을 쓴다).
```

### 팀 토의

설계·방향을 정하거나 아이디어를 넓힐 때 팀원 여러 명에게 토의를 맡기고 **결정 메모**를 받습니다. 중립인 사회자 1명이 진행하고 토론자 1~4명이 발언합니다. 업무 패널과 **에이전트 관찰**이 켜져 있어야 합니다. 관찰이 꺼져 있으면 차례가 끝났는지 알 수 없어 시작이 막힙니다.

#### 역할 목록

업무 패널 위의 🎭 버튼(**토의 역할 목록**)에서 역할 카드를 만들고 고칩니다. 카드 칸은 이름, **토의 스탠스**, **관점·책임**, **판단 기준·금지사항**, **기본 CLI**입니다.

- 스탠스: 사회자(중립)·자유 의견·동조·보강·비판·악마의 대변인·아이디어 발산·종합. 사회자 스탠스는 의견을 내지 않고 지목·수렴 판단·메모 작성만 합니다.
- 역할 목록이나 프로필 편집을 처음 열 때 프리셋 6개(사회자·비판자·악마의 대변인·사용자 관점·유지보수 관점·아이디어 발산)를 그때의 화면 언어로 넣어 줍니다. **프리셋 추가…**로 하나씩 더 넣을 수 있습니다(이미 있는 프리셋도 같은 이름으로 하나 더 생깁니다).
- 프로필 편집의 **토의 기본 역할**에서 팀원마다 기본 역할을 정합니다. 토의를 열 때 미리 채울 값일 뿐 토의마다 바꿀 수 있습니다. 지운 역할을 가리키는 프로필은 "없음"으로 읽습니다.
- **기본 CLI**를 정해 두면 그 역할을 맡은 참가자의 CLI·모델을 이 값으로 미리 채웁니다.

#### 토의 열기

업무 패널 위의 🗣 버튼(**토의 열기**)을 누르고 주제, 맥락(배경·이미 정한 것·제약·참고할 파일), 작업 폴더(절대 경로, 비우면 홈 폴더), 사회자, 토론자, 상한을 정한 뒤 **만들기**를 누릅니다. 참가자 행의 CLI 이름을 펼치면 모델과 추론 강도를, 상한 요약을 펼치면 라운드·시간·비용과 사용량 대기를 바꿀 수 있습니다.

- 참가자마다 역할과 CLI(모델·추론 강도)를 고릅니다. 사회자 칸에는 사회자 스탠스 역할만, 토론자 칸에는 그 밖의 역할만 고를 수 있습니다. CLI는 역할의 기본 CLI → 프로필의 **업무 기본 에이전트** → `claude` 순으로 미리 채웁니다.
- 다른 일을 하는 캐릭터도 참가할 수 있습니다. 토의는 캐릭터의 본 터미널이 아니라 참가자마다 따로 여는 **토의 탭**에서 돌기 때문에 본업을 건드리지 않습니다.
- 만든 토의는 업무 패널의 토의 묶음에 **준비** 카드로 생깁니다. 카드를 누르면 보기 창이 열립니다. **고치기**는 준비 상태에서만, **삭제**는 준비·결론 확인·끝남 상태에서만 됩니다.

#### 진행 방식

보기 창의 **시작**을 누르면 진행합니다. 토의는 한 번에 하나만 진행하므로, 진행 중이거나 멈춘 다른 토의가 있거나 다른 토의 탭이 남아 있으면 시작이 막힙니다. 삭제된 팀원이 참가자에 있어도 막힙니다. 막힌 이유는 버튼 아래에 나옵니다.

1. **첫 라운드(동시·비공개)** — 토론자 전원의 토의 탭이 동시에 열립니다. 각자 서로의 의견을 보지 않고 자기 역할의 관점으로 발언합니다. 전원이 내면 발언을 한꺼번에 공개합니다.
2. **사회자 차례** — 사회자 탭은 이때 처음 열립니다. 사회자는 지금까지의 발언을 보고 셋 중 하나를 고릅니다. 토론자를 순서대로 **지목**해 각자에게 질문을 주거나(지목 한 번이 한 라운드), **사람에게 질문**하거나, **정리**합니다.
3. **지목된 토론자** — 지목 순서대로 답합니다. 뒤 사람은 앞 사람의 발언을 보고 반박·보완합니다. 모두 답하면 다시 사회자 차례입니다.

- 참가자는 모두 `office-discuss say`(앱이 토의 탭에 넣어 주는 제출 명령)로 발언을 냅니다. Claude·Codex는 제출이 없으면 그 차례의 마지막 응답(Stop 훅이 실어 오는 마지막 메시지)이 발언이 됩니다. pi·agy·kilo는 마지막 응답을 읽을 수 없어 제출만 받습니다.
- 앱은 턴이 끝난 신호를 받은 뒤에 발언을 읽습니다. 백그라운드 서브에이전트가 아직 도는 중의 턴 경계는 끝으로 보지 않습니다. 비었으면 1.5초 뒤 한 번 더 읽고, 그래도 없으면 같은 차례를 한 번 다시 요청합니다. 그 차례에도 없으면 "발언 없음"으로 멈춥니다.
- 발언을 받지 못하거나 사회자 지시를 읽지 못하면 한 번 다시 요청하고, 그래도 안 되면 **멈춤**이 됩니다. 멈춘 이유는 보기 창에 나옵니다.
- 토의 탭은 터미널 탭 줄에 뜨고(동시에 5개까지), 진행 중인 발언은 탭에서 볼 수 있습니다. 공개된 발언 전체는 보기 창의 [속기록](#속기록) 탭에서, 참가자마다 최근 발언 한 줄은 오피스의 [회의록 보드](#회의실-연출)에서 봅니다. 끝나면 결정 메모가 남습니다.
- 토의 탭을 직접 닫으면 그 탭의 차례를 기다리던 토의가 멈춥니다. 토의 탭에 쓰다 만 입력이 있어도 차례를 넣지 않고 멈춥니다. **계속**을 누르면 필요한 탭을 다시 엽니다.
- 보기 창의 **멈춤**·**계속**·**끝내기**로 조작합니다. **끝내기**는 결정 메모 없이 바로 끝남으로 보냅니다.
- 앱을 다시 켜면 진행 중이던 토의는 멈춤이 되고, 계속하면 탭을 다시 엽니다. 질문 대기 중이던 토의는 그대로 답을 기다립니다.
- 차례마다 그 탭이 아직 못 본 발언을 함께 넣습니다(탭을 새로 열면 처음부터). 한 차례는 약 192KB까지입니다. 넘치면 긴 발언은 끝부분만 남겨 고르게 줄이고, 그래도 넘치면 오래된 기록부터 빼며 그 사실을 차례에 적습니다. 새 탭의 첫 프롬프트가 넘치면 맥락 칸을 줄입니다.
- 참가자에게 보내는 글(첫 프롬프트·차례 지시)은 화면 언어가 한국어면 한국어, 그 밖에는 영어입니다. 결정 메모의 제목·절 이름과 앱 화면은 화면 언어를 따릅니다.

#### 속기록

보기 창은 **개요**와 **속기록** 두 탭입니다. 창은 늘 개요로 열리고(시작·멈춤·답하기 같은 조작은 개요에 있습니다), 회의록 보드의 행을 누를 때만 속기록 탭으로 바로 열립니다.

- 공개된 발언을 라운드 구분선으로 묶어 시간 순으로 보여 줍니다. 발언마다 화자, 역할, 종류(첫 라운드·발언·사회·사람에게 질문·사람의 답·알림), 시각이 붙고, 본문은 Markdown으로 그립니다. 사회자 지목·정리, 사람과의 문답, 앱 알림(상한·멈춤 등)은 모양을 달리합니다.
- 진행 중이면 새 발언이 아래에 붙습니다. 맨 아래를 보고 있을 때만 따라 내려가고, 위를 읽는 중이면 자리를 지킵니다. 맨 아래에는 말하는 중인 참가자("Bo 말하는 중 · 2분째")가 나옵니다.
- 첫 라운드 발언은 보드와 같이 전원이 낸 뒤 한꺼번에 나옵니다. 그 전에는 "1/3 제출"처럼 제출 수만 보입니다.
- 10줄이 넘는 발언은 앞부분만 보이고 **더 보기**로 펼칩니다.
- 위쪽 칩으로 종류(토론 발언·사회자·사람과 문답·알림)를 끄고 켜며, 참가자 칩을 누르면 그 사람의 발언만 남습니다. 사람의 답과 알림은 화자가 없어 참가자를 고르면 빠집니다.
- **내보내기**는 필터와 상관없이 전체 속기록(머리말·참가자·라운드별 발언 전문)을 임시 HTML로 만들어 기본 브라우저로 엽니다. 파일은 앱 데이터 폴더의 `doc-view/discussion-transcript-<토의 id>.html`이고, 다시 내보내면 덮어쓰며, 다른 문서 미리보기 캐시처럼 7일 뒤 앱을 켤 때 지워집니다.
- 회의록 보드의 행을 누르면 그 참가자의 최근 발언으로 스크롤하고 잠깐 강조합니다. 아직 발언이 없으면 끝으로 엽니다. 업무 패널을 접거나 꺼도 열립니다.

#### 사회자의 질문

사회자는 사람의 결정이나 정보 없이는 더 나아갈 수 없을 때만 사람에게 묻습니다. 그러면 토의가 **질문 대기**가 되고 OS 알림이 뜨며 카드가 강조됩니다. 보기 창의 **답** 칸에 적고 **답하기**를 누르면 다시 사회자 차례로 이어집니다. 질문은 라운드를 늘리지 않습니다. 그 밖에는 사람에게 묻지 않고 끝까지 진행하며, 끝나면 결론 확인을 기다립니다.

#### 상한과 사용량 대기

토의를 열 때 상한을 정합니다. 기본값은 최대 4라운드·30분·$5이고 범위는 1~12라운드, 5~240분, $0.5~50입니다. 카드에는 진행 중 `라운드/최대 · 경과/상한 분 · $비용/$상한`이 나옵니다.

- 진행 시간은 진행 중·정리 중일 때만 흐릅니다. 멈춤·질문 대기 동안은 세지 않습니다.
- 비용은 훅이 주는 턴별 토큰을 API 요율로 셈한 추산입니다. 턴 사용량을 알 수 있는 CLI(Claude·Codex·kilo, agy는 턴 끝에 agy 대화 기록에서)만 셉니다. pi 참가자의 비용은 들어가지 않고, kilo·agy 참가자의 비용이 토의에서 실제로 쌓이는지는 확인하지 못했습니다.
- 상한에 닿으면 사회자에게 **마지막 정리 차례**를 하나 줍니다. 이 차례에서는 더 지목하거나 묻지 못하고, 그때까지 나온 발언으로 메모를 정리합니다. 라운드 상한은 최대 라운드를 마친 뒤의 사회자 차례가 정리 차례가 됩니다. 시간·비용 상한은 발언·지목 단계에서 검사합니다. 이미 끝났지만 아직 받지 않은 발언이 있으면 받은 뒤 정리합니다.
- 정리 차례에서 요약을 받지 못하거나, 정리 차례가 진행 시간 5분 안에 끝나지 않으면 요약 없이 마무리합니다.
- **사용량 대기**(기본 켬, 토의 열기의 체크박스) — 차례를 넣기 전마다 그 참가자의 구독 한도 창이 버틸지 [자동 진행](#자동-진행)과 같은 방식으로 예측합니다. 모자랄 것 같으면 **멈춤(사용량 대기)**으로 두고 한도 창이 리셋되거나 조회값이 넉넉해지면 스스로 이어 갑니다. 앱을 다시 켜도 대기는 이어집니다. **기다리지 않고 계속**은 다음 차례 하나를 검사 없이 보냅니다. 기다리는 동안 **멈춤**을 누르면 스스로 이어 가지 않습니다.

#### 결정 메모

사회자가 정리하거나 상한으로 정리되면 토의는 **결론 확인** 상태가 됩니다. 앱은 결정 메모를 저장하고 토의 탭을 모두 닫은 뒤 OS 알림을 띄웁니다.

- 메모 절: 주제와 맥락, 결론, 근거, 기각된 대안과 이유, 남은 쟁점, 사용자 확인 필요, (아이디어 발산이면) 나온 안을 주제별로, 참가자와 역할. 머리말에는 일시, 진행(라운드·분·비용), 마무리 방식(사회자 정리 또는 어느 상한에 닿아 강제 정리)이 붙습니다. 제목·머리말·절 이름은 앱이 화면 언어로 붙이고, 각 절의 내용은 사회자가 쓴 그대로입니다.
- 보기 창에서 메모를 읽고 **브라우저로 열기**로 크게 볼 수 있습니다. **결론 확인**을 누르면 끝남이 됩니다. 결론 확인 대기 중인 토의는 다음 토의를 막지 않습니다.
- 메모 파일은 앱 데이터 폴더의 `discussions/memos/<토의 id>.md`입니다(macOS `~/Library/Application Support/com.bugcaptor.agent-office/`, 다른 OS는 [수신함 폴더](#다른-프로그램에서-할-일-남기기)와 같은 상위 폴더). 토의를 삭제하면 메모와 참가자의 발언 제출 파일(`discussions/turns/`)도 지워집니다.
- 메모 저장에 실패해도 결론 확인 상태로 가고, OS 알림에 저장하지 못했다고 나옵니다.

#### 읽기 전용 범위

토의 참가자는 코드·문서를 읽고 웹을 조사할 수 있지만 파일을 고치거나 커밋하지 않습니다. 이 규칙은 첫 프롬프트로만 지킵니다. 앱은 권한·도구를 좁히는 플래그를 붙이지 않습니다. 사람 없이 도는 차례가 승인 대기로 멈추지 않게 Claude는 `--permission-mode auto`로, Codex는 `--dangerously-bypass-approvals-and-sandbox`(승인·샌드박스 없음, `--yolo`와 같다)와 웹 조사를 여는 `--search`로 띄웁니다. agy·kilo·pi는 업무 보내기와 같은 자동 승인 플래그로 뜹니다.

권한 플래그로 막으면 발언 제출까지 막혀 진행이 멈추기 때문입니다. 예를 들어 Claude `dontAsk`는 본문에 `{"`가 든 셸 명령을 허용 규칙과 상관없이 거절해 사회자의 JSON 지시가 매번 막혔고, Codex 읽기 전용 샌드박스는 제출 파일 쓰기를 막았습니다.

- 첫 프롬프트는 편집 도구, 셸로 쓰기(`>` 리다이렉션, `sed -i`, `rm` 등), 커밋·푸시·브랜치 전환·설치·빌드, `office-task` 업무 변경을 금지하고 셸은 읽기 명령에만 쓰게 합니다. 제출 명령만 예외라고 적습니다. Claude·Codex에는 명령이 막히면 다시 시도하지 말고 마지막 답변에 발언을 쓰라고 함께 적습니다.
- Codex는 샌드박스 없이 돌므로 읽기 전용은 전적으로 프롬프트 규칙에 달려 있습니다.
- 카드와 보기 창에는 "읽기 전용 · 프롬프트 규칙"이 나옵니다.

#### CLI에서 열기

에이전트나 스크립트도 `office-task --discuss`로 준비 상태의 토의를 만들고, `ctl discuss`로 시작·답하기·결과 조회를 할 수 있습니다. 사용법은 [에이전트·CLI에서 토의 열기](#에이전트cli에서-토의-열기)에 있습니다. 앱이 띄운 에이전트 세션은 사용자가 팀 토의를 부탁할 때만 토의를 만들고, 시작은 사람에게 맡기도록 안내받습니다.

#### 회의실 연출

토의가 진행·질문 대기·정리·멈춤 상태인 동안 오피스에 연출이 붙습니다. 결론 확인이나 끝남이 되면 원래 동선으로 돌아갑니다.

- **회의실** — 모든 풍경에 5석 회의실이 있고(풍경마다 바닥·의자·테이블 그림이 다릅니다), 참가자마다 의자가 하나씩 정해집니다. 사회자는 서쪽 끝, 토론자는 북쪽·동쪽에 앉습니다. 본업이 쉬는 참가자는 본인이 걸어가 앉습니다. "쉰다"는 탕비실과 같은 기준입니다. 본 터미널 세션이 떠 있지 않고 알림 대기도 없어야 합니다. 본 세션이 떠 있으면 프롬프트에서 쉬고 있어도 자리에 남고, 알림 대기 중이면 보스 앞 줄이 먼저입니다.
- **분신** — 본인이 의자에 앉아 있지 않은 동안 그 의자에는 반투명한 분신이 앉습니다. 본업 중이라 자리에 남은 참가자는 토의 내내 분신이 대신하고, 쉬던 참가자도 걸어오는 동안에는 분신이 먼저 앉아 있습니다. 본인이 의자에 도착하면 분신이 사라지고, 본인이 일하러 일어나면 그 자리에 바로 다시 나타납니다. 책상이 모자라 오피스에 보이지 않는 팀원도 분신으로 회의실에 앉습니다. 분신을 누르면 본인을 누른 것과 같습니다.
- **발언 말풍선** — 차례를 받아 말하는 중인 참가자에게 말풍선이 뜹니다. 회의실에 앉은 쪽(본인이나 분신)의 머리 위에 뜨고, 자리에 남은 본인에게는 뜨지 않습니다. 알림 느낌표가 말풍선보다, 말풍선이 생각 말풍선보다 먼저입니다.
- **의사봉** — 토의가 이어지는 동안 회의실의 사회자(본인이나 분신) 머리 왼쪽에 작은 의사봉이 붙습니다.
- **회의록 보드** — 회의실 오른쪽(오른쪽에 자리가 모자라면 왼쪽)에 참가자마다 한 줄씩 이름, 최근 발언, 경과("방금"·"3분 전")가 나옵니다. 말하는 중이면 "말하는 중 · N분째"가 나오고, 사회자가 사람에게 물었으면 "질문: …"이 나옵니다. 사회자의 지목은 "→ 이름: 질문"으로 보입니다. 발언은 앞부분만 잘라 보여 주고(요약 호출 없음), 마우스를 올리면 조금 더 깁니다. 행을 누르면 보기 창의 [속기록](#속기록) 탭이 그 발언을 가리키며 열립니다. 경과는 30초마다 다시 셉니다. 첫 라운드 발언은 전원이 낸 뒤 공개될 때 함께 나옵니다. 보드 머리를 누르면 접히고, 접힘 여부는 이 기기에 기억합니다.

#### 아직 확인하지 못한 것

토의 흐름은 단위 테스트와 가짜 백엔드(`npm run gui:shot`)로 확인했습니다. 다음은 실제 환경에서 확인하지 못했습니다. 문제가 보이면 알려 주세요.

- 실제 CLI로 토의를 처음부터 끝까지 돌리는 흐름, 그리고 실제 사회자가 지시 JSON(특히 정리 형식)을 지키는지
- 실제 앱의 수신함 가져오기와 `ctl discuss start`·`answer` 중계 경로
- agy·kilo의 `office-discuss say` 제출과 kilo의 비용 집계, 참가자가 프롬프트의 읽기 전용 규칙을 얼마나 잘 지키는지, 일반 Codex 세션에서 `office-task --discuss`로 토의 만들기(Codex 샌드박스가 수신함 쓰기를 막을 수 있음)
- 사회자 의사봉과 자리 ↔ 회의실 이동은 단위 테스트만 했고 화면으로는 보지 못했습니다
- 속기록 탭은 단위 테스트와 가짜 백엔드 화면으로, 내보내기 HTML 변환은 Rust 테스트로만 확인했습니다. 실제 앱에서 브라우저가 열리는지는 확인하지 못했습니다
- 분신과 회의록 보드는 단위 테스트와 가짜 백엔드 화면으로만 확인했습니다. 실제 앱의 창 크기 변화와 `ctl discuss watch` 중계는 확인하지 못했습니다

### 터미널 보기 ↔ 대화 보기

터미널 패널 오른쪽 위 **💬** 버튼을 누르면 지금 탭이 "대화 보기"로 바뀝니다. CLI는 터미널에서 그대로 돌고, 보기만 Claude·Codex·Antigravity(agy) 전사를 채팅처럼 그립니다. 사람 말(👤), 에이전트 말(캐릭터 얼굴, 마크다운), 도구 호출과 결과(접힘), 대화에 실린 이미지(누르면 확대)가 보입니다. 웹 상태판처럼 최신이 맨 위이고, 도구 결과·이미지는 그 호출 블록 안에서 아래로 붙습니다(서브에이전트 블록도 같음). 맨 위를 보고 있으면 새 항목이 그대로 보이고, 아래로 내려 읽는 중이면 자리를 지킵니다. 언제든 **⌨**나 **터미널 보기**로 돌아갑니다. 보기는 탭마다 기억합니다.

- **복사·다운로드**는 메시지, 코드 블록, 도구 호출과 결과의 텍스트를 각각 복사할 수 있습니다. 이미지는 썸네일과 확대 화면에서 복사하거나 원본을 저장할 수 있습니다. 에이전트가 대화에서 링크한 작업 폴더 안의 파일(최대 24MB)도 저장할 수 있습니다. 다운로드를 누르면 저장 위치를 고르는 창이 열립니다.
- **권한 요청·질문**(Claude): 카드로 떠서 여기서 허용·거부하거나 선택지에 답합니다. 터미널에도 같은 대화상자가 떠 있어 어느 보기에서든 먼저 답한 쪽이 반영됩니다(웹 상태판 카드도 같은 요청입니다).
- **입력칸**(맨 위): CLI가 턴을 마치고 입력을 기다리면 같은 세션에 바로 넣습니다(Enter 보내기, Shift+Enter 줄바꿈). 작업 중이거나 답을 기다리면 버튼이 **대기열에 넣기**로 바뀌고 [보낼 대기열](#보낼-메시지-대기열)에 쌓입니다. 터미널에 쓰다 만 입력이 있으면 넣지 않고 기다리니, 그때는 터미널 보기에서 지우거나 보냅니다.
- **지금 상태 줄**: 최신 블록 바로 위에 "생각 중… 42초"(점이 움직임)·"Bash 실행 중…"·"멈췄을 수 있습니다"(작업 중인데 터미널 출력이 20초 넘게 없음)·"입력을 기다림"이 보여, 생각하는 중인지 멈췄는지 가릴 수 있습니다.
- 슬래시 명령 메뉴처럼 전사에 남지 않는 화면은 터미널 보기에서만 보입니다. Claude·Codex·Antigravity 세션이 아닌 탭은 "읽을 대화가 없습니다"로 나옵니다. agy 전사는 훅이 알려 준 대화 파일을 따라가므로 에이전트 관찰이 켜진 세션에서 첫 턴 뒤부터 보입니다(agy는 권한·질문 카드가 없습니다).

### 보낼 메시지 대기열

대화 보기와 웹 상태판의 입력은 같은 대기열을 씁니다. 에이전트가 작업 중일 때 보낸 말은 입력칸 아래 목록에 쌓이고, 턴이 끝날 때마다 하나씩 같은 세션에 들어갑니다(한 번에 하나, 각각 새 턴). Claude는 예외로, 작업 중이고 답을 기다리는 권한 요청·질문이 없으면 쌓지 않고 바로 넣습니다(Claude Code가 다음 도구 호출 뒤에 반영). 쌓여 있던 말도 Claude가 다시 작업 중이 되면(예: 권한에 답한 뒤) 턴 끝을 기다리지 않고 들어갑니다. 터미널 포그라운드로 Claude를 가리므로 Windows에서는 늘 턴 끝을 기다립니다. 들어가기 전에는 **✕**(웹은 **빼기**)로 뺄 수 있습니다. 캐릭터마다 20개까지 쌓입니다.

- 넣기 직전에 터미널에 쓰다 만 입력이 있으면 넣지 않고 몇 초 뒤 다시 해 봅니다(목록 아래에 까닭이 보임).
- 터미널을 재시작하거나 새 세션이 열리면 옛 대화를 향한 메시지는 버리고 "세션이 바뀌어 대기열을 비웠습니다"를 보입니다. 앱을 끄면 대기열도 사라집니다.
- Claude에 작업 중 넣은 말은 Claude 자기 대기열에서 기다립니다. 그 사이 터미널에서 ↑·Esc를 누르면 Claude가 그 말을 입력창으로 되돌리고 제출하지 않습니다. Agent Office는 Claude 전사로 이를 알아채서, 웹·앱의 **작업 중단** 직후였으면 턴을 끊고 바로 보내고, 그 밖에 사람 입력 없이 되돌려졌으면 다시 Enter로 넣습니다. 터미널에서 사람이 직접 되돌렸으면 건드리지 않고 목록 아래에 알립니다(터미널에서 Enter로 보내면 됩니다).
- **중단하고 바로 보내기**: 작업 중일 때 입력칸 옆에 나옵니다. 대기열을 건너뛰고 진행 중인 턴을 끊은 뒤 바로 넣습니다. Claude는 Claude Code의 지금 보내기 키(`chat:sendNow`, 기본 Ctrl-X Ctrl-S — 키를 바꿨으면 동작하지 않음)로, 다른 CLI는 Esc로 끊고 1초 뒤 넣습니다. 권한 요청·질문이 떠 있으면 글이 대화상자로 들어가므로 먼저 답해야 합니다. 이미 쌓인 대기열은 그대로 이어집니다.

### 터미널 탭 우클릭 메뉴

캐릭터를 클릭하면 터미널이 열리고 상단에 세션 탭이 나타납니다. **탭을 우클릭**하면 자주 쓰는 동작이 뜹니다.

- **터미널 재시작** / **이전 세션 이어하기** / **터미널 종료** — 셸·세션을 다시 만들거나 되살리거나 끝냅니다. 현재 작업 폴더가 프로필의 시작 폴더와 다르면(시작 폴더의 하위 폴더인 경우는 제외), 현재 폴더를 새 시작 폴더로 저장할지, 이번만 현재 폴더에서 재시작할지, 설정된 시작 폴더로 돌아갈지 고를 수 있습니다.
- **작업 폴더 보기** — 프로필의 시작 폴더를 앱 내 탐색기 또는 시스템 파일 탐색기로 엽니다.
- **폴더 열기 설정…** — 모든 프로필에 사용할 탐색기와 폴더 편집기를 고릅니다. **설정 → 시스템**에서도 바꿀 수 있습니다. 기본값은 앱 내 탐색기와 VS Code입니다.
- **VS Code로 열기** / **Sublime Text로 열기** — 선택한 편집기로 에이전트가 현재 작업 중인 폴더를 엽니다. 현재 폴더가 관측되지 않았으면 프로필의 시작 폴더를 사용합니다.
- **OS 터미널로 열기** — 프로필의 시작 폴더(cwd)를 외부 터미널로 엽니다(cwd가 있어야 활성화).
- **셸 출력을 에디터로 보기** / **일기 보기** — 세션 출력이나 캐릭터 일기를 봅니다.
- **세션 로그 보기** — 지난 세션 기록을 10개씩 훑어보고, 하나를 골라 편집기로 열거나 학습자료로 정리합니다.
- **프로필 편집** — 이름·아키타입·외형·시작 명령어 등을 수정합니다.
- **퇴근** — 세션을 종료하고 캐릭터를 내보냅니다(나중에 다시 소환).
- **캐릭터 삭제** — 세션과 프로필을 완전히 제거합니다.

### 단축키로 터미널 열기

**설정 → 단축키** 탭에서 에이전트마다 터미널을 바로 여는 키와, 알림을 준 에이전트로 가는 키를 지정합니다. 앱 창에 포커스가 있을 때만 동작하고, 터미널에 입력 중이어도 셸보다 먼저 받습니다.

- 칸을 누르고 키를 누르면 기록됩니다. Esc는 취소, ×는 지우기입니다.
- 빈 칸은 단축키가 없는 상태입니다. 흐린 글자는 추천값이며 **추천값**을 눌러야 저장됩니다.

| | macOS 추천값 | Windows·Linux 추천값 |
|---|---|---|
| 에이전트 목록 1~9번째 | ⌘⌥1 ~ ⌘⌥9 | Ctrl+Alt+1 ~ Ctrl+Alt+9 |
| 알림 준 에이전트로 가기 | ⌘⌥J | Ctrl+Alt+J |

- 에이전트 키: 그 에이전트 터미널을 엽니다. 이미 앞에 열려 있거나 퇴근 중이면 아무 일도 하지 않습니다.
- 알림 키: 남은 알림 중 **가장 오래된** 알림의 에이전트로 갑니다. 열면 그 알림이 지워지므로 다시 누르면 다음 알림으로 갑니다. 남은 알림이 없으면 아무 일도 하지 않습니다.
- 셸·TUI가 받는 키(Ctrl+글자, Alt+글자), 앱·OS가 이미 쓰는 키(⌘W, ⌘1~9, Ctrl+1~9 등), 다른 칸과 겹치는 키는 저장하지 않고 이유를 보여 줍니다. ⌘ 또는 Ctrl+Alt 조합이나 F키를 쓰세요.
- 키는 물리 키 위치로 기록합니다. Windows·Linux에서 AltGr(=Ctrl+Alt)로 다른 글자를 찍는 자판(예: 독일어 AltGr+7 = `{`)은 그 글자 입력으로 보고 단축키로 치지 않습니다.

### 외부 OS 터미널 열기

프로필 메뉴와 저장소 점검의 **OS 터미널로 열기**는 Windows Terminal과 실행 중인 iTerm에서 기존 창의 새 탭을 우선합니다. Windows Terminal은 최근 사용 창, iTerm은 현재 창에 새 탭을 만들며 창이 없으면 새 창을 엽니다. 기존 탭의 작업과 시작 폴더는 변경하지 않습니다.

macOS에서 iTerm을 선택하면 처음 사용할 때 자동화 권한을 요청할 수 있습니다. 권한이 없거나 iTerm이 실행 중이 아니면 기존 방식으로 iTerm을 열고, iTerm을 열 수 없으면 Terminal을 시도합니다. macOS Terminal과 Linux 터미널은 기존 열기 방식을 유지합니다. 새 탭 생성 여부가 불확실한 오류에서는 중복 생성을 피하기 위해 재시도하지 않고 실패를 알립니다.

### 예쁜 캐릭터를 쉽게 만드는 법

시드 자동 생성 스프라이트도 되지만, **프롬프트를 복사해 이미지 생성 AI로 만든 그림을 올리는 것**이 원하는 외형을 얻는 가장 쉬운 방법입니다.

1. 탭 우클릭 → **프로필 편집**.
2. **초상화 추가 프롬프트**·**스프라이트 추가 프롬프트**에 원하는 외형을 적습니다(예: "빨간 망토를 두른 마법사"). 각 칸은 그 이름의 그림에만 덧붙습니다.
3. **스프라이트 프롬프트 복사**(스프라이트), **초상 프롬프트 복사**(초상화), **미니미 프롬프트 복사**(소환수) 버튼으로 프롬프트를 클립보드에 복사합니다.
4. 이미지 생성 AI에 붙여넣어 그림을 만듭니다.
5. **스프라이트 업로드** / **이미지 업로드** / **미니미 업로드** 버튼으로 올리면 끝(크롭·배경 투명화 지원). 로컬에 `codex` CLI가 설치돼 있으면 **Codex로 생성** 모드에서 초상·스프라이트·미니미를 바로 만들 수도 있습니다.

> **미니미**는 서브에이전트가 일할 때 캐릭터 머리 옆에 뜨는 소환수입니다. **미니미 추가 프롬프트**를 비워 두면, 본체의 외형·역할에 어울리는 소환수를 알아서 그려 달라는 문구가 프롬프트에 자동으로 들어갑니다.

> 업로드·생성 버튼은 **이미 만든 캐릭터의 프로필을 편집할 때** 나타납니다. 먼저 캐릭터를 만든 뒤 외형을 다듬으세요.

> **키 컬러**는 시드와 아키타입에서 결정되어 세 프롬프트에 그대로 실리는 색입니다. 프로필 편집창 외형 섹션에서 색과 hex를 볼 수 있고, 마음에 들지 않으면 **스프라이트 재생성**(시드 변경)이나 아키타입 변경으로 바꿉니다.

## 개발자용 명령

### 저장소 작업 규칙 — 정본

- 코드에서 알 수 있는 설계·명세 문서는 만들지 않는다. `docs/`에는 사용 안내, 운영 절차처럼 코드로 알 수 없는 것과 코드 길잡이([README.md](README.md))만 둔다. 작업 과정은 이슈에 남긴다.
- 기본적으로 `main`에서 직접 작업하고 로컬 커밋한다. 별도 브랜치·워크트리·PR은 요청이 있을 때만 사용한다. 커밋 금지 등 개별 작업 지시가 있으면 그 지시를 우선한다.
- 임의로 푸시하지 않는다.
- 커밋 메시지는 한국어 한 줄로 간명하게 쓴다. AI를 공동저자로 넣지 않는다.
- 화면 문자열은 하드코딩하지 않고 `src/shared/i18n/locales/`에 넣는다. 검사는 `noHardcodedHangul.test.ts`가 담당한다.
- 검증은 `npx tsc --noEmit`, `npx vitest run --dir src`, `cargo test --manifest-path src-tauri/Cargo.toml`이다. vitest만으로는 공유 타입 사용처의 누락을 잡지 못하므로 타입 검사를 함께 한다.
- UI 변경을 화면으로 확인할 때는 브라우저 확장이나 computer use 대신 `npm run gui:shot`(헤드리스 Chrome + 가짜 백엔드)을 먼저 쓴다. 클릭·입력 재현은 `--script`로 한다. 사용법은 `scripts/gui-shot.mjs` 머리 주석에 있다.
- `AGENTS.md`·`CLAUDE.md`는 git 추적 제외인 로컬 안내 파일이다. 클론에서 읽어야 할 일반 규칙은 이 절에 둔다.

### 빌드 캐시 청소

`npm run tauri`의 `pretauri` 훅이 `scripts/sweep-target.mjs`를 실행한다. 개발 빌드는 증분 컴파일을 위해 `src-tauri/target/`에 캐시를 남긴다.

별도로 정리하려면 `npm run sweep`, 이번 실행만 건너뛰려면 `AGENT_OFFICE_SKIP_SWEEP=1`을 사용한다. `AGENT_OFFICE_SWEEP_DAYS`는 잔존물 기준 일수(기본 3)다. `cargo install cargo-sweep`으로 설치하면 `deps/`까지 정리한다.

설치용 빌드(`build:bundle`, `build:mac`, `build:mac:dmg`, `build:win`, `install:mac`, `install:win`)는 Cargo 1.91 이상이 필요하다. 빌드가 성공하면 저장소 안에 쌓인 개발·릴리즈 Rust 중간 파일도 함께 정리한다. 설치 파일과 앱 실행 파일은 기존 경로에 남는다. 빌드가 실패하면 이번 빌드의 임시 디렉터리만 정리한다. 릴리즈 빌드를 반복하면서 캐시를 재사용하려면 `npm run tauri build`를 사용한다.

### 요구사항

- Node 20.19+ 또는 22.12+ (현재 Vite 7의 `engines.node` 기준)
- Rust 툴체인 ([rustup.rs](https://rustup.rs))
- Tauri v2 기반 — macOS/Windows/Linux 지원. Linux는 시스템 패키지가 추가로 필요합니다([Tauri 사전 준비](https://v2.tauri.app/start/prerequisites/)).

### 개발 서버

```bash
npm install && npm run tauri dev
```

`./scripts/build-and-run.sh`(= `npm start`)는 위 두 단계를 알아서 처리합니다. Windows는 `scripts\build-and-run.cmd`(= `npm run start:win`)가 같은 역할입니다.

### 릴리즈 빌드

```bash
npm install && npm run build:bundle
```

결과물은 `src-tauri/target/release/`에 생성됩니다(macOS `.dmg`, Windows `.msi`/`.exe`, Linux `.deb`/`.AppImage`).

### Windows 빌드·설치

```powershell
npm run build:win      # NSIS 인스톨러만 빌드 (src-tauri\target\release\bundle\nsis\)
npm run install:win    # 빌드 + 현재 사용자 계정에 조용히 설치(/S) + 실행
```

설치 위치는 `%LOCALAPPDATA%\agent-office`이고 관리자 권한이 필요 없습니다. `install:win`은 `scripts\build-and-run.ps1 --install`과 같습니다.

### macOS 서명

설치 절차는 [README의 Quick Start](../README.md#quick-start)에 있습니다. 여기서는 개발자용 명령만 정리합니다.

```bash
npm run cert:mac       # 자체 서명 인증서 생성 — 최초 1회
npm run build:mac      # 빌드 + 서명 (설치는 안 함)
npm run install:mac    # 빌드 + 서명 + 응용 프로그램에 설치

tccutil reset All com.bugcaptor.agent-office   # 최초 1회, 서명 전 잔재 청소
```

`npm run build:mac`·`install:mac`은 `--bundles app`으로 `.app`을 만듭니다. 배포용 DMG는 `npm run build:mac:dmg`로 만들고, 다른 인증서를 쓰려면 이름을 넘깁니다.

```bash
APPLE_SIGNING_IDENTITY="Agent Office Local Signing" npm run build:mac:dmg
```

서명하지 않으면 designated requirement가 빌드마다 바뀌어 권한 프롬프트가 계속 반복됩니다. 원리·인증서 종류별 차이·배포 방식은 [macos-signing.md](macos-signing.md)가 정본입니다. 이 절은 macOS 전용이며, Windows·Linux 빌드와는 무관합니다.

### 테스트

```bash
npx vitest run --dir src                                # 프런트
cargo test --manifest-path src-tauri/Cargo.toml         # 네이티브
npx tsc --noEmit                                       # 타입 검사
```

테스트는 실패 처리, 상태 전이, 저장·IPC 형식, 동시성, 경계값처럼 실제 회귀를 잡는 동작을 검증합니다. 직접 만든 리터럴을 다시 확인하거나 구현의 상수·문구를 그대로 복사한 검사는 두지 않습니다. 같은 회귀를 이미 잡는 검사가 있으면 중복 검사를 줄입니다. 번역 키·보간 누락, 픽셀 데이터 규격, 색상 대비처럼 정적 데이터라도 사용자 동작에 영향을 주는 검사는 유지합니다.

화면 확인은 `npm run gui:shot`으로 합니다. Tauri 빌드 없이 렌더러를 헤드리스 Chrome과 가짜 백엔드로 띄워 스크린샷을 남기고, `--script`로 클릭과 입력을 재현합니다. 사용법은 `scripts/gui-shot.mjs` 머리 주석에 있습니다. 가짜 백엔드라 Rust 동작과 실제 웹뷰(WKWebView·WebView2) 차이는 확인하지 못합니다.

`src/shared/contract-fixtures/`는 Rust의 실제 serde 출력·입력과 비교합니다. `JSON.parse()` 결과에 TS 타입을 붙이는 것만으로는 타입 불일치를 검증할 수 없습니다. TS·Rust 미러 타입은 함께 검토하고, 프런트 사용처의 누락은 `npm run typecheck`로 확인합니다.
